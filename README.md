# yadori（宿り）

対話するAIに、続く記憶・気持ち・性格を持たせ、道具が変わっても同じ相手として話し続けるためのプログラムです。

会話は出来事として保存され、次に話しかけられたとき、こちらが指示しなくても関係する記憶が思い出されます。気持ちは会話で動いて時間とともに薄れ、性格は長い時間をかけて変わります。夢を手動で起こすと、記憶を読み直して整理します。

> [!IMPORTANT]
> 端末と Discord から話しかけて一往復でき、Claude Code と Codex の端末での操作には、同じ記憶と気持ちを持ったまま付き添えます。気持ちは会話で動いて時間で薄れ、性格は同じ動きからゆっくり変わり、夢を起こせば記憶を読み直して残すものを選び要点の層を作ります（どれも薄い作り）。ほかの対話する道具への付き添い、気がかり、宿りから話しかけることはこれからです。何が決まっていて何が決まっていないかは [`docs/`](docs/) を読んでください。

## apt で導入する

Ubuntu 24.04 / 26.04、Debian 13 の amd64 に対応しています。[導入・更新の手順](packaging/apt/README.md)に従って配布元を登録し、`sudo apt install yadori` で導入します。版ごとの配布物と変更内容は [Releases](https://github.com/yadori-dev/yadori/releases) にあります。

## 動かす

apt で導入した場合は `yadori` を使います。ソースから試す場合は、開発環境で `uv run yadori` を使えます。

`yadori --help` で命令と引数の一覧を読めます。ヘルプは設定前でも読め、標準出力へ表示して成功（終了状態 0）で終わります。不正な命令や引数は標準エラーへ案内を出し、失敗（終了状態 1）で終わります。

まず `yadori setting` で名前・呼び名・持ち主・性格や話し方の文章と、使う道具の順序を設定します。AI の導入やログインは設定の質問には不要です。未設定のまま対話可能な端末で `yadori`、`yadori codex`、`yadori claude`、`yadori agy`、`yadori chat` を起動しても、同じ設定へ進みます。保存後は元の作業場所で起動を続けます。取消・入力終了・保存失敗では起動しません。端末が対話できない場合は質問せず、`yadori setting` を案内します。

```console
$ yadori setting
（名前・呼び名・持ち主・名乗りの文章・道具の優先順を質問し、確認して保存）
$ yadori
対話起動: codex を使います
（そら として Codex を起こします）

$ yadori chat
（そら が居ます。空行で終わります）
> トマトを植えました
そら: いいですね。日当たりはどうですか。
>
```

後日の `yadori setting` は「名前を変更する」「性格を変更する」「別の人物へ切り替える」「デフォルトのモデル順を変更する」のメニューを表示します。名前の項目では名前だけ・呼び名だけ・持ち主だけを選んで編集できます。性格は名乗りの自由な文章として複数行入力し、単独の `.` で確定します。未入力で `.` を入れると現在値を保持します。`/cancel` で編集を取り消してメニューへ戻り、保存確認では `y` で確定します。

共通の優先順の既定は **Codex → Claude Code → agy** です。画面の「デフォルトのモデル順」はこの道具の順序を指し、個別の AIモデル名とは別です。未導入または用途に未対応の候補は理由を表示して飛ばします。選んだ後のログイン切れや実行失敗では別の道具へ再送しません。`yadori claude` などの明示指定はその起動だけを上書きします。chat、Discord、夢の要約、評価下書きの判定も同じ順序を使います。変更は次の起動・処理開始から反映し、起動中の Discord は再起動が必要です。

### 設定の保存と旧版からの移行

保存先は `YADORI_HOME/settings.toml`（既定は `~/.yadori/settings.toml`）です。記憶の `memories.sqlite` は移動しません。旧 `dweller.toml` と `identity.md` は、新しい設定が無い間はそのまま読めます。初回の編集保存で入力済みの値を取り込み、旧ファイルも残します。**移行後に編集するのは `settings.toml`** です。旧版で引数なしの `yadori` を端末チャットとして使っていた場合は `yadori chat` に変更してください。

```toml
version = 1
active = "sora"
priority = ["codex", "claude", "agy"]

[people.sora]
id = "sora"
name = "そら"
nickname = "そら"
owner = "あなたの名前"
identity = "わたしはそらです。ていねいな言葉で話し、園芸を好みます。"
```

別の人物は同じ形の `[people.umi]` などの表を手で用意し、setting の人物切替から選べます。表のキーと `id` は一致させ、既存の人物の識別子を変えないでください。呼び名や名乗りを変えても識別子は保持するので同じ記憶を引き継ぎます。旧設定で `id` を省いていた場合は、移行前の呼び名を識別子として固定します。人物を切り替えて戻すと、その人物の記憶・状態から続けられます。

優先順は候補を省いても構いませんが、空の順序・重複・未知の名前は使えません。必要なら共通の `[models]` 表で `codex`、`claude`、`agy` ごとのモデル名を指定できます（内部の応対・要約・判定用）。旧人物設定の `model` は Claude 用として保持し、他の道具へ渡しません。Codex と agy は指定が無ければ道具の既定モデルを使い、対話起動のモデル設定は各道具の既存の約束を引き継ぎます。

返事のあとの一行は、その往復で宿りの気持ちがどちらへどれだけ動いたか（共通の順序で選んだ道具が答える）と、いまの値です。値は −1（沈む）から +1（明るい）で、動きを積んで経過時間で薄めた和です（半減期 6 時間。仮置き）。性格は同じ動きを長い半減期（90 日）で小さく（0.1 倍）積んだ傾向です。今の気持ちと性格は次の返事の前置きにも渡ります。

```console
$ yadori state
気持ち: +0.10 落ち着いている（半減期 6 時間）
性格: +0.01 落ち着いている（半減期 90 日、動きは 0.1 倍で効く）
動き（新しい順）:
  2026-09-01 16:45  +0.3  ほっとした  「やっと通った！原因はタイポだった」
  2026-09-01 16:45  -0.2  心配です  「三時間やってもテストが通らなくて、もう疲れた」

$ yadori state --at 2026-09-01T16:45:29+09:00
気持ち: -0.20 落ち着いている（2026-09-01T16:45:29+09:00 時点）
性格: -0.02 落ち着いている（2026-09-01T16:45:29+09:00 時点）
動き（新しい順）:
  2026-09-01 16:45  -0.2  心配です  「三時間やってもテストが通らなくて、もう疲れた」
```

`state` で、いつ、どの往復で、どちらへどれだけ動いたかを新しい順に読めます。応対の傾向が変わったと感じたら、どの出来事が効いたかをここで辿ります。

### 根拠が足りないときに探し直す

`yadori codex`、`yadori claude`、`yadori agy` で話している宿りは、過去の根拠が足りないとき、自分で検索語を考えて記憶を探せます。最初は短い候補だけを見て、必要な原文と限られた前後を読みます。毎回のMCP登録や検索コマンドの入力は要りません。

一往復の上限は検索3回、検索と原文取得で8回、受け付けた応答は12000文字です。原文は1000文字ずつ返し、最後まで読めなければ未取得と明示します。参照と取得位置は同じ往復だけで有効です。上限後に次の往復へ続きを引き継ぐ仕組みはありません。分からない決定を作らず、不足点の確認へ戻ります。

人物は起動時の設定に固定され、設定を切り替えても今の会話へ別人物の記憶は混ざりません。検索や取得を会話として保存したり、思い出した回数へ足したりはしません。専用起動の `recall.sqlite` には、その起動中の検索履歴と予算を持ち、起動を終えると専用履歴と一緒に片付けます。

`yadori_memory` は予約した接続名です。同名の設定や、この接続を拒否・無効化する指定があれば、上書きせず理由を示します。許可するのは記憶の検索と取得の二つだけです。agyはLinuxの対応版で、既存の設定・履歴の分離を維持します。

この入口はDiscordと専用の `chat` には追加していません。また、検索候補を短くすることと総トークンの削減は別です。道具の説明やモデルの追加往復も増えるため、総トークンや待ち時間が必ず減るとは限りません。要件と測定条件は [INC-082](docs/210_increments/INC-082.md) にあります。

### 夢を起こす

```console
$ yadori dream
夢: 2026-09-01 14:46 から 16:45 までの 11 件を読み、4 件を選びました
要点: 2 件を残しました
  - テストが通らずに疲れていたが、原因はタイポで、通ってほっとした
  - 図書館で借りた小説の返却日は来月の五日
気づき: 無し
選んだ 4 件になぞった記録を残しました

$ yadori dream
夢: 新しい記憶がありません。読み直しませんでした
```

夢では、短い返答が何への承認・否定・継続・選択だったかも調べます。原文はそのまま残し、同じ会話の直接の先行往復を根拠にできる場合だけ、説明を別に保存して検索に使います。結果に補完・保留・対象外・失敗件数と未処理の有無を表示し、説明から対象と根拠の原文を読めます。所属の分からない古い記憶や途中の文脈が欠ける記憶は保留します。一度に100件まで進め、失敗した分は次の `yadori dream` で再試行します。

話しかけられていない間に、宿りが前回の夢より後の記憶を読み直して整理します。人の眠りで記憶に起きることとして複数の学説が一致する点（なぞられる、残るものは選ばれる、要点の形へ変わる、つながり全体は弱まる）に寄せてあります。どれも定説として固まったものではなく、限界は[理論資料](docs/910_references/理論/README.md)に書いてあります。

- **選ぶ**: 思い出された往復、気持ちが大きく動いた往復、同じ話題が繰り返し出た往復を残す（基準は仮置き）
- **要点にする**: 選んだ往復を話題ごとにまとめた一行を、原文とは別の層に残す。要点は共通の順序で選んだ道具が書き、渡るのは名乗りとその往復の発話と返事だけ。原文は変わらない
- **なぞる**: 選んだ往復に思い出した記録を積む。選ばれなかった往復には積まない。思い出す順に効くのは、思い出しやすさの増分（`AC-016`）から
- **気づき**: 離れた話題が結びついたときだけ一行添える。無くてよい

前回の夢で残した要点は次の返事の前置きに添い、`state` にも出ます。定期に起こすのは持ち主の道具（cron など）に任せます。夢で気持ちを動かすことはしません（学説が割れています）。

名乗りは項目に分けず、一続きの文章で書きます。起動のたびに読み直し、変わっていれば新しい版になります。以前の版は消えません。

記憶も名乗りも `YADORI_HOME`（既定は `~/.yadori`）に置き、リポジトリへは入れません。

応対の文章は、共通の順序で選んだ手元の道具を通して作ります。持ち主の定額契約で動くため、AIモデルの提供元への鍵は要りません。

> [!WARNING]
> `ANTHROPIC_API_KEY` を設定しないでください。設定すると定額契約ではなく従量課金で動きます。

### Claude Code に付き添う

apt で導入済みなら、次の準備は不要です。ソースから使う場合は、yadori のリポジトリで一度だけ手元の命令として入れます。

```console
$ uv tool install --editable .
```

次に、普段どおりの Claude Code で定額契約へログインし、付き添わせたい作業場所を一度開いて、そこにある設定や MCP（外の道具へつなぐ仕組み）を信頼するか確認します。そのあと、同じ作業場所で次を実行します。

```console
$ yadori claude
（そら として Claude Code を起こします）
```

これ以降は普段の Claude Code と同じように使います。話しかけるたびに、宿りの名乗り、いまの気持ちと性格、直近の会話、関係する記憶が返事の前提へ自動で渡ります。返事まで終わった一往復だけが記憶され、途中で止めた発話は残りません。

普段の Claude Code からは、AIモデル、見た目、許可、承認済みの MCP、指示とスキルのうち、安全に一回の起動へ写せるものだけを借ります。`CLAUDE.md`、普段の会話履歴、自動記憶、バックグラウンド処理、接続先を変える設定、外部サービス側の連携は借りません。利用者ごとの保存内容や常時動く処理を持つプラグインも借りず、理由を画面へ出します。起動中の履歴と設定は `YADORI_HOME` の一時置き場へ分け、終了時に捨てます。

作業場所の設定がまだ信頼されていない、`.mcp.json` の利用可否が決まっていない、定額契約以外の接続先が選ばれている場合は、何を確かめればよいかを出して起動しません。これは普段の Claude Code 側で内容を確認してから、もう一度 `yadori claude` を実行してください。

### Codex に付き添う

Codex にログイン済みの端末で、付き添わせたい作業場所から `yadori codex` を実行します。宿りの名乗り、記憶、気持ちは同じ設定を使います。Codex のデスクトップ画面は対象外です。

### 起動前の取り込みと夢

通常の `yadori`、`yadori claude`、`yadori codex`、`yadori agy`、`yadori chat` は、初回に起動前の準備を選べます。取り込み元と動作を人物ごとに保存し、次から外部会話の取り込み→自身の夢→会話の順に進みます。`yadori setting` の「起動前の取り込みと夢」で、自動・毎回選ぶ・実行しないを変更できます。

今回だけ変える場合は `yadori --prepare ask` で個別に選び、`yadori --prepare skip` で会話へ進みます。`--prepare auto` は保存済みの取り込み元を自動で処理します。質問できない入力では、設定済みの自動処理だけを行います。起動前に Ctrl+C を押すと実行中の子も止め、確定した分を残して会話へ進みます。

取り込みは新規200往復まで、夢も一回分までとし、残りを表示します。外部会話は取り込んだ時点で検索でき、宿り自身の夢や気持ちへ変換しません。取り込みが0件でも自身の未処理会話があれば夢を行います。夢では既存と同様に、選んだ会話を対話する道具へ渡します。保存先を確かめられない場合は起動を断ります。

### 普段の会話ログを選んで取り込む

宿りとして起こしていない三つのCLIの会話も、選んだ人物へ取り込めます。まず確認し、`--apply` を付けた場合だけ保存します。人物の識別子は `settings.toml` の `people` のキーです。

```console
yadori import claude --from ~/.claude/projects --person sora
yadori import claude --from ~/.claude/projects --person sora --apply
yadori import codex --from ~/.codex/sessions --person sora --apply
yadori import agy --from ~/.gemini/antigravity-cli/brain --person sora --apply
```

ファイルまたはディレクトリを指定でき、複数なら `--from` を繰り返します。agyは会話別の `.system_generated/logs/transcript_full.jsonl` を読みます。要約や入力履歴から応対を推測しません。現在の実物で確認した形式はClaude Code 2.1.270、Codex 0.154.0、agy 1.2.2です。古い形式などで完成を確認できない往復は理由を表示し、取り込みません。

完成した利用者発話と応対を原文で保存し、出典には元の道具・会話・発話を持ちます。検索時も外部の会話だと表示します。同じ出典の再実行やファイル移動で重複せず、原文が変われば上書きしません。事前確認の破損・競合では書き込まず、保存中の障害では確定した往復だけを残して件数を表示します。未完の末尾は次回へ残します。取り込み自体では名乗り・気持ち・思い出した回数を増やしません。

### agy に付き添う

Linux では Antigravity CLI 1.2.1 / 1.2.2 に対応しています。追加検索の実入口は 1.2.2 で確認しています。`agy` と `bubblewrap` を導入し、普段の agy で Google アカウントへのログイン、初回案内、作業場所の信頼確認を済ませます。その作業場所で起動します。

```console
$ yadori agy
（そら として agy を起こします）
```

話しかける前に同じ宿りの名乗り・記憶・気持ちが渡り、完成した一往復を記憶します。検索、ファイル編集、端末操作を使え、変更の承認は agy で行います。普段の agy の設定と会話履歴へは書き込みません。

今回は技能・プラグイン・MCP の継承、下位担当・予約・背景作業、会話の再開・分岐・担当切替には対応しません。別の会話へ切り替えようとすると起動を終えます。API キーを使う設定や、対応していない環境では理由を示して起動しません。

文脈を渡せないときは返事を作らず止まります。記憶へ保存できなかった完成済みの往復は回復用の原文を残し、次回の起動前に再試行します。完成状態を確認できない場合は、その記録の場所を示して起動を断ります。原文を確かめる前に回復用の領域を削除しないでください。[設定と履歴の扱い](docs/010_decisions/ADR-022-agyの設定と履歴をLinuxの起動ごとに分ける.md)に境界を記載しています。

### Discord で話す

```console
$ cat ~/.yadori/discord.toml
token = "<Discord の bot のトークン>"
owner_id = 123456789012345678

$ yadori discord
（そら が Discord に居ます。終わるには Ctrl-C）
```

Discord から宿りへ話しかけられます。端末で話した続きが Discord でも続き、Discord で話した続きが端末でも続きます。覚えていることも、今の気持ちも性格も、同じ一人ぶんです。

繋ぐには、Discord の開発者向けの画面で bot を作り、次の二つを済ませてください。

1. アプリケーションを作り、Bot のトークン（その bot を見分けるための長い文字列）を取る
2. 作った bot を自分のところへ招き、直接の会話（DM）で話しかける

受け取るのは直接の会話だけなので、**MESSAGE CONTENT INTENT（届いた言葉の中身を読む許可）を入れる必要はありません。**

トークンと、自分のユーザーID（Discord の画面で自分の ID をコピーできます）を `~/.yadori/discord.toml` に書きます。**トークンはリポジトリへ入れないでください。**

応対を作れなかったときは、Discord には応対できないことだけが返り、理由は宿りを動かしている手元の画面に出ます。

答えるのは、その `owner_id` の人からの直接の会話だけです。サーバーの部屋の言葉はそもそも受け取らず、他の人の言葉、宿り自身の言葉には答えません（[ADR-019](docs/010_decisions/ADR-019-Discordへはbotとして繋ぎトークンを持ち主の手元に置く.md)）。動かし続けるのは持ち主の道具（`systemd` や `tmux` など、閉じたあともプログラムを動かし続ける仕組み）に任せます。

## 思い出す質を測る

次はリポジトリの `evals/recall.toml` を使う例です。apt 版には評価セットを同梱しないため、`--eval` で手元の評価セットを指定してください。

```console
$ yadori measure
埋め込み: sirasagi62/ruri-v3-30m-ONNX（fastembed-0.8.0） 添え書き: 覚える「検索文書: 」 問い合わせ「検索クエリ: 」
大きさ 0.15GB / 読み込み 0.416秒 / 一発話 0.003秒
条件: 直近6往復・上限5件・下限0.85
5問中 5問で期待したやりとりが上位3件に入った
出てはいけないやりとりが出た問: 0問

$ yadori measure --floor 0.80
（今の条件と、下限を変えた条件の差を問ごとに出す）

$ yadori measure --embedding characters --floor 0.21
（語の重なりだけを見る埋め込みで測る。下限の意味は埋め込みごとに違うため、添えて指す）

$ yadori measure --eval <手元の評価セット> --embedding multilingual --floor 0.50
（前の多言語の AIモデルで測る。未取得なら「取得します」と大きさと取得先を出してから取得する）
埋め込み: paraphrase-multilingual-MiniLM-L12-v2（fastembed-0.8.0） 添え書き: 無し
大きさ 0.25GB / 読み込み 0.921秒 / 一発話 0.076秒
条件: 直近6往復・上限5件・下限0.85
…
```

`--embedding` には、`characters`（語の重なり）、`multilingual`（前の多言語の AIモデル `paraphrase-multilingual-MiniLM-L12-v2`）、試す埋め込みの名前（`ruri-v3-30m`（既定）、`ruri-v3-130m`、`multilingual-e5-small`）、埋め込みを動かす道具の対応表にある AIモデルの `配布元/名前` を指せます。`+` で並べると両方の道から渡します。指せない名前を渡すと、指せる名前の一覧が返ります。結果の冒頭には、埋め込みの出自（AIモデルの名前、動かした道具の名前と版）、添え書き（その AIモデルが文の前に付けるよう定めている決まった語。覚える側と問い合わせ側で違うものがある）、取得した物の大きさ、AIモデルの読み込みにかかった時間、一発話を数の並びにする時間が並びます。近さの下限の意味は埋め込みごとに違うので、数だけを見比べず、埋め込みごとに下限を振って比べてください。

リポジトリの `evals/recall.toml` は架空の会話です。実際の会話から作った評価セットは手元に置き、`--eval` で指してください。架空の会話は書いた本人が話題も語も選ぶため都合よく当たり、そこで測った値は実際の会話での質を保証しません。

AIモデルは初回に取得し、`YADORI_HOME` の下の `models/` に置きます。以後は外へ繋がずに動きます。

### 実際の会話の記録から評価セットの下書きを作る

```console
$ yadori evals draft --from ~/.claude/projects/<作業場所の記録> --out ~/yadori-evals/real-recall.toml
候補を引いた 埋め込み: sirasagi62/ruri-v3-30m-ONNX（fastembed-0.8.0） / 条件: 直近6往復・候補10件・下限0.3 / 判定: opus
記録: 28 セッション、中身のある発話 151 件（読めず飛ばしたファイル 0）
覚えさせる発話: 106 件
問: 44 問（後の発話が前の話題を指していそうなもの。すべて確認前）
  ~/yadori-evals/real-recall.toml の各問を読み、残す問は confirmed = true にしてください
  候補は思い出す仕組みが引いたものだけです。拾えなかった組（下限を下回る、件数の上限から外れた）は手で足せます。直近の範囲の組は測れないので足しません
```

対話する道具（Claude Code、Codex）が手元に残した記録のディレクトリを `--from` で指すと、後の発話ごとに、宿りの思い出す仕組み（文を数字に変えて意味の近さで探す。会話で使うものと同じ）で前の発話の候補を引き、その発話と候補だけを共通の順序で選んだ道具に渡して同じ話題かを判定させます。同じ話題と判定された組が問として並びます。問ごとに `overlap`（語の重なりの度合い。小さいほど言い換え）が添うので、それを手掛かりに読み、期待が妥当な問は `confirmed = true` に、違う問は消します。確認前の問が残ったままでは測れません。

候補は思い出す仕組みが引いたものだけなので、その仕組みが拾えない組は下書きに出ません。手で問を足してください。この下書きで埋め込みどうしを比べると、引いた側の埋め込みに有利に偏ります（[ADR-017](docs/010_decisions/ADR-017-実際の会話の記録を判定のために対話する道具へ渡す.md)）。

記録が増えたら、同じ下書きを指して `--append` を付けます。下書きの冒頭にある `[covered]`（前回の範囲。どの時刻までの記録をどのディレクトリから読んだか）より後に増えた記録だけが読まれ、新しい問が末尾に確認前として足されます。前回の問と、人が付けた確認・消した問・変えた名前は一字も変わりません。

```console
$ yadori evals draft --from ~/.claude/projects/<作業場所の記録> --out ~/yadori-evals/real-recall.toml --append
候補を引いた 埋め込み: sirasagi62/ruri-v3-30m-ONNX（fastembed-0.8.0） / 条件: 直近6往復・候補10件・下限0.3 / 判定: opus
前回の範囲: 2026-08-31 15:20 まで、<記録のディレクトリ>、飛ばしたファイル 0、28 セッション
前回の下書き: 覚えさせる発話 106 件、問 44 問
今回: 新しい記録 3 セッション、新しい発話 21 件（読めず飛ばしたファイル 0）、判定へ渡した発話 15 件、候補が無く渡さなかった発話 6 件
覚えさせる発話: +17 件
問: +4 問（すべて確認前）。前回の 44 問とその確認はそのまま
  ~/yadori-evals/real-recall.toml の新しい問を読み、残す問は confirmed = true にしてください
```

追記できるのは `[covered]` を持つ下書きだけです。埋め込みの AIモデルや添え書き、条件、判定の AIモデル、記録のディレクトリが前回と違うときは足さず、新しいファイルへ作り直すよう伝えます。既定の埋め込みを替えた後は、前の埋め込みで作った下書きには追記できず、作り直しになります。埋め込みを動かす道具の版だけが違うときは足し、注意を出します。少しずつ追記するより多く貯めてから追記する方が、直近の範囲で外れる組が少なく、問は多く取れます。

判定のために渡るのは、後の発話と数件の候補の文章だけです。選んだ道具は実行時に表示します。記録元とは別の相手へ渡る場合があります。返事、時刻、作業場所は渡らず、記録を丸ごと渡すこともありません。出力先はリポジトリの外を指してください。`--append` を付けないときは、既にあるファイルには書きません。

## 何が普通のAI対話と違うか

対話するAIは、セッションが変わると前回を覚えていません。記憶を外に置いても、AIが自分から探しに行かなければ使われません。yadori は、話しかけられた文章そのものから関係する記憶を探し、AIが「思い出す」という操作をしなくても踏まえて答えられる状態にしてから渡します。

もう一つの違いは、話しかけられていない間も動いていることです。記憶の整理、気持ちの変化、気がかりの生成は、会話がなくても進みます。宿りは呼ばれたときだけ現れるものではなく、常に居るものとして作ります。

## どこで話すか

宿りの本体は常駐するひとつのプログラムで、話す場所はその出ていく先です。

| 出ていく先 | そこで起きること |
|---|---|
| Discord | 宿り自身の言葉で話す。宿りから話しかけるのもここ |
| Claude Code / Codex / Gemini | 作業に付き添う。返事は各道具が作り、宿りは思い出した記憶と今の状態を渡す |

同じ記憶と同じ気持ちを持ったまま、複数の場所へ出ていきます。
