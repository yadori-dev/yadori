# 記憶・気持ち・夢

[READMEへ戻る](../../README.md) · [使い方の一覧](README.md)

## 状態を読む

返事のあとの一行は、その往復で宿りの気持ちがどちらへどれだけ動いたか（共通の順序で選んだ道具が答える）と、いまの値です。値は −1（沈む）から +1（明るい）で、動きを積んで経過時間で薄めた和です（半減期 6 時間。仮置き）。性格は同じ動きを長い半減期（90 日）で小さく（0.1 倍）積んだ傾向です。今の気持ちと性格は次の返事の前置きにも渡ります。

```console
$ yadori state
気持ち: +0.10 落ち着いている（半減期 6 時間）
性格: +0.01 落ち着いている（半減期 90 日、動きは 0.1 倍で効く）
動き（新しい順）:
  2026-09-01 16:45  +0.3  ほっとした  「やっと通った！原因はタイポだった」
  2026-09-01 16:45  -0.2  心配です  「三時間やってもテストが通らなくて、もう疲れた」

$ yadori state --at 2026-09-01T16:45:29+09:00
気持ち: -0.20 落ち着いている（2026-09-01T16:45:29+09:00 時点）
性格: -0.02 落ち着いている（2026-09-01T16:45:29+09:00 時点）
動き（新しい順）:
  2026-09-01 16:45  -0.2  心配です  「三時間やってもテストが通らなくて、もう疲れた」
```

`state` で、いつ、どの往復で、どちらへどれだけ動いたかを新しい順に読めます。応対の傾向が変わったと感じたら、どの出来事が効いたかをここで辿ります。

## 根拠が足りないときに探し直す

`yadori codex`、`yadori claude`、`yadori agy` で話している宿りは、過去の根拠が足りないとき、自分で検索語を考えて記憶を探せます。最初は短い候補だけを見て、必要な原文と限られた前後を読みます。毎回のMCP登録や検索コマンドの入力は要りません。

一往復の上限は検索3回、検索と原文取得で8回、受け付けた応答は12000文字です。原文は1000文字ずつ返し、最後まで読めなければ未取得と明示します。参照と取得位置は同じ往復だけで有効です。上限後に次の往復へ続きを引き継ぐ仕組みはありません。分からない決定を作らず、不足点の確認へ戻ります。

人物は起動時の設定に固定され、設定を切り替えても今の会話へ別人物の記憶は混ざりません。検索や取得を会話として保存したり、思い出した回数へ足したりはしません。専用起動の `recall.sqlite` には、その起動中の検索履歴と予算を持ち、起動を終えると専用履歴と一緒に片付けます。

`yadori_memory` は予約した接続名です。同名の設定や、この接続を拒否・無効化する指定があれば、上書きせず理由を示します。許可するのは記憶の検索と取得の二つだけです。agyはLinuxの対応版で、既存の設定・履歴の分離を維持します。

この入口はDiscordと専用の `chat` には追加していません。また、検索候補を短くすることと総トークンの削減は別です。道具の説明やモデルの追加往復も増えるため、総トークンや待ち時間が必ず減るとは限りません。要件と測定条件は [INC-082](../210_increments/INC-082.md) にあります。

## 夢を起こす

```console
$ yadori dream
夢: 2026-09-01 14:46 から 16:45 までの 11 件を読み、4 件を選びました
要点: 2 件を残しました
  - テストが通らずに疲れていたが、原因はタイポで、通ってほっとした
  - 図書館で借りた小説の返却日は来月の五日
気づき: 無し
選んだ 4 件になぞった記録を残しました

$ yadori dream
夢: 新しい記憶がありません。読み直しませんでした
```

夢では、短い返答が何への承認・否定・継続・選択だったかも調べます。原文はそのまま残し、同じ会話の直接の先行往復を根拠にできる場合だけ、説明を別に保存して検索に使います。結果に補完・保留・対象外・失敗件数と未処理の有無を表示し、説明から対象と根拠の原文を読めます。所属の分からない古い記憶や途中の文脈が欠ける記憶は保留します。一度に100件まで進め、失敗した分は次の `yadori dream` で再試行します。

話しかけられていない間に、宿りが前回の夢より後の記憶を読み直して整理します。人の眠りで記憶に起きることとして複数の学説が一致する点（なぞられる、残るものは選ばれる、要点の形へ変わる、つながり全体は弱まる）に寄せてあります。どれも定説として固まったものではなく、限界は[理論資料](../910_references/理論/README.md)に書いてあります。

- **選ぶ**: 思い出された往復、気持ちが大きく動いた往復、同じ話題が繰り返し出た往復を残す（基準は仮置き）
- **要点にする**: 選んだ往復を話題ごとにまとめた一行を、原文とは別の層に残す。要点は共通の順序で選んだ道具が書き、渡るのは名乗りとその往復の発話と返事だけ。原文は変わらない
- **なぞる**: 選んだ往復に思い出した記録を積む。選ばれなかった往復には積まない。思い出す順に効くのは、思い出しやすさの増分（`AC-016`）から
- **気づき**: 離れた話題が結びついたときだけ一行添える。無くてよい

前回の夢で残した要点は次の返事の前置きに添い、`state` にも出ます。[起動前の準備](importing.md)で実行するほか、定期実行は持ち主が用意します。夢で気持ちを動かすことはしません（学説が割れています）。
