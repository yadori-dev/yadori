# 利用者とシナリオ

## 関係する立場

| 立場 | 何をしたいか |
|---|---|
| 話す人 | 続きとして話し、前提を説明し直さずに済ませる。相手の側にも積み重ねがあってほしい |
| 作業に付き添わせる人 | 対話する道具で仕事をしながら、前に決めたことを踏まえた応対を受ける |
| 自分の宿りを立てる人 | 他人の記憶と混ざらない自分の宿りを、自分の手元で動かす。用途に応じて複数を立てる |
| 保守する開発者 | 思い出す条件、AIモデル、保存の形を入れ替えながら、記憶と経緯を失わずに動かし続ける |

一人が複数の立場を兼ねる。機能を使う立場と、実装を保守する開発者を同じものとして扱わない。

## 使い方の流れ

日中は対話する道具で仕事をし、その会話が記憶として積まれる。仕事から離れているときは、Discord で宿り自身と話す。夜、宿りは記憶を整理し、そこで気づいたことを気がかりとして持つ。翌日、気がかりが強ければ宿りの側から話しかける。

## シナリオ

### SC-001 昨日の続きを話す

話す人は、前回と別のセッションで話しかける。前提を説明していないが、宿りは前回決めたことと、そのとき何を迷っていたかを踏まえて答える。話す人は、何を踏まえて答えたのかを必要なら確かめられる。

### SC-002 作業の最中に、前に決めたことを思い出してもらう

作業に付き添わせる人は、対話する道具で実装を進める。過去に「この方法は採らないと決めた」経緯があり、話す人はそれを覚えていない。宿りは、話しかけられた文章から関係する記憶を見つけ、道具が答えを作る前に渡す。話す人は探させる指示を出していない。

### SC-003 道具を変えても同じ相手として続く

話す人は、午前は対話する道具で作業し、午後は別の道具を使い、夜は Discord で話す。三つとも同じ記憶と同じ気持ちを持った相手として続く。返事の口調は道具ごとに揃わないが、覚えていることと今の気分は同じである。

### SC-004 話しているうちに気持ちが動く

話す人と宿りが、うまくいかない作業について長く話す。宿りの気持ちが動き、その状態は会話が終わっても残る。次に話しかけたとき、時間が経っていれば薄れており、間が短ければ残っている。

### SC-005 夜、記憶が整理される

誰も話しかけていない間に、宿りはその日の記憶を読み直し、まとめ直す。原文は消えない。整理の中で気づいたことを気がかりとして持つ。何を読み直し、何に気づいたかは後から読める。

### SC-006 朝、宿りの側から話しかけてくる

気がかりが強くなり、宿りは自分から Discord へ話しかける。話す前に、その気がかりについて確かめる。話す人はその日、まだ一度も話しかけていない。

### SC-007 言わずに済ませる

宿りは気がかりを持っていたが、話す前に確かめたところ、話す人が既に自分で解決していた。宿りは話しかけず、その気がかりは消える。話す人はその日、宿りから何も受け取らない。

### SC-008 同じことを何度も気にする

同じ話題の気がかりが、何日も続けて生まれる。宿りはそれを別々の件として積まず、一つの強い気がかりとしてまとめる。話す人から見ると、宿りが長く引っかかっていることが一件として分かる。

### SC-009 見当違いの返事の理由を調べる

話す人は、まったく関係のない話を持ち出された返事を受け取る。そのやりとりについて、宿りが何を思い出し、それぞれがどれくらい近いと判定されたかを読む。話す人は、思い出す条件のどこがずれているかを判断できる。

### SC-010 思い出す条件を変える

保守する開発者は、意味の近さの閾値と、一度に思い出す件数を変える。変更の前後で、あらかじめ用意した発話と期待する記憶の組に対して測り、良くなった点と悪くなった点を並べて読む。感覚ではなく、測った値で採否を決める。

### SC-011 意味検索のAIモデルを入れ替える

保守する開発者は、埋め込みを作るAIモデルを新しいものへ入れ替える。インデックスを全部捨て、保存してある会話の原文から作り直す。作り直した後も、同じ発話に対して以前と比べられる結果が出る。会話の原文は一件も失われていない。

### SC-019 実際の会話から評価セットを作る

保守する開発者は、対話する道具が手元に残した記録のディレクトリを指す。前の発話と、後になって同じ話題を指した発話の組が、評価セットの下書きとして手元に出る。組には語の重なりの度合いが添い、言い換えの組を見分けられる。開発者は組ごとに期待が妥当かを読み、残すか消すかを決めてから測る。会話の原文はリポジトリへ入らない。

### SC-020 下書きに増えた記録の分だけを足す

保守する開発者は、前に作った評価セットの下書きと同じファイルを指して追記する。前回より後に増えた記録だけが読まれ、その発話だけが候補を引かれて判定へ渡り、新しい問が末尾に確認前として足される。前回の問とその確認は一字も変わらない。どこまで読んだかは下書きに残り、読める。

### SC-012 育ち方を後からたどる

話す人は、宿りの応対が以前と変わったと感じる。いつごろ、何があって、どちらへどれだけ動いたかを順に読む。望まない変化であれば、どの出来事が効いたかを特定できる。

### SC-014 宿りに名乗りを与える

自分の宿りを立てる人は、その宿りが誰であるかを文章で書く。名前、自分の呼び方、話し方、自分について変わってほしくない事柄を、項目に分けず一続きの文章で書く。書いた後に話しかけると、書いたとおりの名前と話し方で応対が返る。会話を重ねて記憶が増え、気分が変わっても、書いた部分は変わらない。

### SC-015 名乗りを書き直す

話す人は、しばらく使ったあと話し方を変えたくなり、名乗りを書き直す。書き直した後の応対は新しい名乗りに従う。以前の名乗りも読めるため、変える前と後で応対がどう変わったかを比べられる。過去の応対については、それがどの名乗りで作られたかを読める。

### SC-018 別の言い方で尋ねても思い出す

話す人は、前に「ベランダにトマトの苗を植えました」と話した。しばらく経って「植物の世話について教えてください」と尋ねる。「トマト」とも「植えた」とも言っていないが、宿りはその件を踏まえて答える。同じ話題を別の言葉で言い直しただけであり、話す人は前に何と言ったかを覚えていない。

### SC-017 よく話すことほど詳しく覚えている

話す人は、何か月も同じ仕事の話を続けている。その話題に触れると、宿りは細かい経緯まで踏まえて答える。一方、一年前に一度だけ話して以来触れていない話題に軽く触れても、宿りはそれを持ち出さない。話す人がその件を名指しで尋ねると、宿りは思い出して答える。

### SC-016 用途ごとに宿りを分ける

話す人は、いまの宿りとは別に、扱う話題も応対も違う宿りをもう一つ立てる。それぞれへ違う名乗りを書き、名前で呼び分ける。片方と話した内容は、もう片方に思い出されない。片方の気分が沈んでも、もう片方はその影響を受けない。同じ常駐がどちらも動かしている。

### SC-013 自分の宿りを立てる

自分の宿りを立てる人は、自分の手元で常駐を動かし、自分の Discord とつなぐ。自分の記憶は自分の宿りにだけ入り、他の人の宿りと混ざらない。会話がどこに保存され、外部のどの相手へ渡るかを、使い始める前に読める。
