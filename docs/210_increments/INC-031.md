## 体験の変化

保守する開発者は、試す埋め込みを名前で指して、今と同じ入口（`measure --embedding`）で測る。埋め込みを動かす道具の対応表に無いものも、ONNX 形式（学習済みの AIモデルを、学習に使った道具に依らず動かせる形）で配られていれば同じ入口から指せる。結果には満たした問と混入した問に加えて、埋め込みの出自、添え書き、取得する物の大きさ、AIモデルの読み込みにかかった時間、一発話を数の並びにする時間が並ぶ。指せない名前を渡すと、指せる名前の一覧が出る。名前は正しいが AIモデルがまだ手元に無ければ、大きさを告げてから取得する。動かすものが手元に無ければ、測る前に何を導入すればよいかが返る。鍵は要求しない。

測るのは、実際の会話から作った手元の評価セット（人が書いた 29 問。すべて前の話題を別の言い方で指す発話で、試す埋め込みで引いたものではない）と、リポジトリの架空の評価セット（5 問）である。下書きの道具が作った下書きは今の埋め込みが引いた候補からできていて、埋め込みどうしを比べると引いた側に有利に偏るため（[ADR-017](../010_decisions/ADR-017-実際の会話の記録を判定のために対話する道具へ渡す.md)）、物差しにしない。

近さの値の幅は埋め込みごとに違い、今の埋め込みで 0.5 の下限が別の埋め込みでは 0.8 を超えることもある。下限を揃えて数だけを見比べず、埋め込みごとに**代表の点**を選ぶ。

- 下限を 0.30 から 0.95 まで 0.05 刻みで振り、実際の会話の評価セットで測る
- 混入した問が **1 問以下**（今の埋め込みの既定の下限 0.50 での混入の数。PR #28 で測った値）に収まる下限のうち、満たした問が最大の点を代表にする。同数なら混入が少ない側、それも同じなら下限が高い側を採る
- 今の埋め込みも同じ手順で代表を求める（既定の下限 0.50 では 15 問・混入 1 問。代表は今回の測定で求め直す）
- 採るのは、代表どうしで満たした問が今の埋め込みより **3 問以上多く**、かつ代表の下限で架空の評価セットを測って満たした問が今の埋め込みの既定の下限での値（5 問中 4 問・混入 0 問。PR #28）より減らず、混入した問が増えない埋め込みに限る。架空の評価セットは `AC-006` と `AC-017` の物差しでもあるため、そこで減る埋め込みは採らない。29 問は期待を持ち主側の一人が決めたもので問によっては期待の妥当性が揺れるため、2 問以下の差は揺れの範囲とみて替えない。混入の条件を満たす下限が一つも無い埋め込みは代表を持たず、採らない
- 差が小さいときも良くなった問と悪くなった問を名指しで読み、次の判断材料として PR に残す。今の埋め込みの代表の下限が既定の 0.50 と違っても、下限だけを替えることは今回扱わず、その値を PR に残して別の Issue にする
- 採る埋め込みが二つ以上あれば、満たした問が多い側、同数なら取得する物が小さい側を採る

採ったら既定の埋め込みと下限（代表の下限）が替わり、次の起動で新しい埋め込みのインデックスが作り直される（`SPEC-025-002`）。原文は失われず、鍵は要らない。既定を替えると、それまでに作った評価セットの下書きは埋め込みの AIモデルの名前が前回と違うため追記できず（`SPEC-037-001`）、新しく作り直す。これは偏りを受ける手当てでもある（ADR-017）。どの埋め込みも基準に届かなければ既定を変えず、測った値と採らない理由を PR に残す。どちらの結末でも、試す埋め込みの名前は指せるまま残す（`INC-025` と同じ）。話す人の側に操作は無い。

話す人は、採られた場合、店の種類を別の言い方で呼んだり、固有名を縮めたり、同じ道具を別の語で指したりしても、前の話題を踏まえた応対を受ける。埋め込みが大きくなれば起動と一往復は遅くなりうるため、読み込みと一発話の時間を測って重さを比べる。

この増分では 29 問を物差しとして仮定し、問を増やすことは扱わない。日本語向けは `ruri-v3` の一系列（大小の二つ）で、どれも届かなかったときの結論はその系列に限る。別系列として `static-embedding-japanese` を試したが、配布物に道具が求める素性と語彙の設定ファイルが無く、そのままでは読めなかったため今回は足さない。

```console

埋め込み: sirasagi62/ruri-v3-30m-ONNX（fastembed-0.8.0） 添え書き: 覚える「検索文書: 」 問い合わせ「検索クエリ: 」
大きさ 0.15GB / 読み込み 1.2秒 / 一発話 0.003秒

埋め込み: sirasagi62/ruri-v3-30m-ONNX（fastembed-0.8.0） 添え書き: 覚える「検索文書: 」 問い合わせ「検索クエリ: 」
大きさ 0.15GB / 読み込み 1.2秒 / 一発話 0.003秒
条件: 直近6往復・上限5件・下限0.85
29問中 21問で期待したやりとりが上位3件に入った
出てはいけないやりとりが出た問: 1問
（問ごとの良くなった・悪くなった）

$ uv run python -m yadori measure --embedding ruri
測れません: ruri は指せる埋め込みではありません。指せるもの: characters、multilingual、ruri-v3-30m、ruri-v3-130m、multilingual-e5-small。埋め込みを動かす道具の対応表にある AIモデルは 提供元/名前 で指せます
```

数値は増分の中で決める。読み取れることは、埋め込みごとに満たした問・混入した問・添え書き・大きさ・時間が並び、指せない名前には指せるものが返ることである。

## 手段の候補

- `IDEA-031-001`: 提供元へ鍵で繋ぐ埋め込みを測る。会話のたびに課金が積み上がり、定額契約で動かす前提（[ADR-016](../010_decisions/ADR-016-応対は対話する道具を通して作り、その道具の文脈を持ち込まない.md)）を崩す。採らない
- `IDEA-031-002`: 文の埋め込みを学習と同じ道具（sentence-transformers と PyTorch）で動かす口を足す。配られている埋め込みを何でも指せるが、導入する物が増え（PyTorch 本体の配布物だけで 0.53GB。PyPI の表示。既定では GPU 用の依存も付いてさらに増える）、測る側と会話側で埋め込みを動かす道具が二つになる。採らない
- `IDEA-031-003`: 今の道具（fastembed）が持つ「対応表の外の AIモデルを登録する口」を使い、ONNX 形式で配られているものを登録して動かす。新しい依存は無く、会話側と同じ道具で測れる。日本語向けは提供元が ONNX を配っていないものが多いが、有志の変換版がある。試したところ `ruri-v3-30m` の変換版は初回の取得込みで 6.7 秒で読み込め、3 文の変換は 0.008 秒、数の並びの長さは 256 で正規化されていた。**採る。** 有志の変換版は、元を動かして突き合わせることはせず（元を動かす道具を入れないため）、数の並びの長さと正規化と、配布元が公表する例文の近さを再現することで確かめる。届かなかったときの結論は、その変換版に限る
- `IDEA-031-004`: 配られていない埋め込みを自分で ONNX 形式へ変換して手元に置く。変換には PyTorch と変換の道具が要る。今回は使わない。別系列（`GLuCoSE-base-ja-v2` など）を足す必要が出て、かつ変換版が無いときに限って使う

測る埋め込みは次のとおりである。大きさと数の並びの長さは配布元の表示で、実際に取得した大きさは測って PR に書く。

| 試す埋め込み | 大きさ | 数の並びの長さ | 動かし方 | 確かめたこと | なぜ測るか |
|---|---|---|---|---|---|
| `ruri-v3-30m` | 0.15GB | 256 | 有志の変換版 `sirasagi62/ruri-v3-30m-ONNX` を登録 | 登録して動かし、数の並びを得た | 日本語向けで最も小さい。今の埋め込み（0.22GB）より小さい |
| `ruri-v3-130m` | 0.53GB | 512 | 有志の変換版 `sirasagi62/ruri-v3-130m-ONNX` を登録 | 変換版が配られていることを配布元の一覧で確かめた。動かしていない | 同じ系列で大きい側。大きさに見合う伸びがあるかを見る |
| `multilingual-e5-small` | 0.47GB | 384 | 提供元が配る ONNX `intfloat/multilingual-e5-small` を登録 | ONNX が配られていることを配布元の一覧で確かめた。動かしていない | 日本語を含む多言語で、今の埋め込みより新しい。日本語向けとの差を見る |

`ruri-v3` は覚える側に「検索文書: 」、問い合わせ側に「検索クエリ: 」、`multilingual-e5` は両側に「query: 」を付ける作法である。付けずに測ると本来の質が出ず、日本語向けは効かなかったという誤った結論になる。どこに作法を持つかは設計で決める。

## 要件とシステムテスト

| 要件と根拠 | 必要な振る舞い |
|---|---|
| `SPEC-031-001`（`AC-020`）試す埋め込みを名前で指して同じ入口から測れる | `measure --embedding <名前>` で、既定の埋め込み、語の重なり、登録した試す埋め込み、埋め込みを動かす道具の対応表にある AIモデル（`提供元/名前` の形）のいずれも指せ、`+` で並べて二つの道からも測れる。指せない名前（登録に無い名前、対応表に無い `提供元/名前`）を渡したときは何も取得せずに理由を返し、理由に指せる名前の一覧と、対応表の AIモデルの指し方を含める。名前は正しいが AIモデルが手元に無く外へ繋がるときは、配布元の表示の大きさ（登録した試す埋め込みは登録に書いた値、対応表の AIモデルは道具が持つ値）と取得先を画面に出してから取得する。取得済みなら鍵が無く外へ繋がらなくても測れる。取得済みでなく外へ繋がらないときと、動かすものが手元に無いときは、測る前に理由を返し、何をすればよいかを含める。登録した試す埋め込みが返す数の並びは、配布元が公表する長さと正規化と例文の近さを再現する（変換版が壊れていない） |
| `SPEC-031-002`（`AC-020`）結果の冒頭に出自と重さが並ぶ | 測った結果の冒頭に、埋め込みの出自（AIモデルの名前、動かした道具の名前と版。登録した試す埋め込みでは、同じ元の AIモデルの別の変換版と区別できる名前。添え書きを定めるものは添え書きも出自に含み、語を変えればインデックスが作り直される）、覚える側と問い合わせ側の添え書き（無ければ無し）、取得する物の大きさ、AIモデルの読み込みにかかった時間、一発話を数の並びにする時間が、条件（直近の往復数、上限、下限）と共に出る。条件を変えて二度測るときも埋め込みの行は二度出る。大きさは手元に取得したファイルから求めた値、時間は今回の実行で測った値である。読み込みは最初に数の並びを作るときに一度だけ起き、その時間は一発話の時間に含めない |
| `SPEC-031-004`（`AC-020`）添え書きは側ごとに作法どおりに付く | 試す埋め込みが添え書きを定めるものなら、覚える文にはその埋め込みが定める覚える側の語、問い合わせの文には問い合わせ側の語が付いて数の並びになる。定めないものには何も付かない。結果の行に出る添え書きは、実際に付けた語である |
| `SPEC-031-003`（`AC-020`）既定を替えたら、既定の下限と説明はその埋め込みで測り直した値になる | 既定の埋め込みを替えたときは、引数を付けずに測った結果の埋め込みの行と条件の行が新しい埋め込みと代表の下限を示し、混ざり始める下限と必要なものが出なくなる下限が思い出し方の説明に残る。実物に当てて固定した観測値（数の並びの長さ、言い換えの近さ、下限）は替えた埋め込みで撮り直したものになる。替えても以前の埋め込みで覚えた保存先の原文は失われず、起動時にインデックスが作り直される（`SPEC-025-002` の振る舞いのまま）。替えないときは既定も説明も変わらない |

### 個々のシステムテスト

確かめ方は行ごとに書く。**自動**は決まった値を返す埋め込みと差し替えで通常のテストに置く。**契約**は取得済みの実物に当てる契約テスト（`just test-contract`）に置く。**手動**は手元の評価セットと実物で通し、結果を PR に書く。添え書きが渡る文字列そのものの確認は、設計の段で結合テストとして起こす。

### 設計判断
