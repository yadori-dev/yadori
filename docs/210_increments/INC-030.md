# INC-030 実際の会話の記録から評価セットの下書きを作る

| 項目 | 内容 |
|---|---|
| Issue | #30 実際の会話の記録から評価セットの下書きを作れるようにする |
| PR | 未作成 |
| 選んだ受入基準 | `AC-018` 記録から評価セットの下書きが出る |

## 体験の変化

保守する開発者は、対話する道具が手元に残した記録の置き場を指す。中身のある発話が一往復ずつ時刻の順に並び、後の発話が前の話題を指していそうな件が、評価セットの下書きとして手元に出る。件は同じ作業場所（同じディレクトリで動いた記録）の中だけで探す。件の期待ごとに語の重なりの度合いが添うため、言い換えの件を見つけやすい。開発者は件ごとに期待が妥当かを読み、残すか消すかを決める。確かめていない件が残ったままでは測れない。確かめた下書きは、`INC-018` の仕組みでそのまま測れる。

千を超えるセッションを人が読んで数十件を書き写していた作業が、読んで決めるところだけになる。

会話の原文は手元に留まる。出力先にリポジトリの中を指すと断る。判定のために発話は対話する道具（Claude Code）へ渡る。Claude Code の記録は普段と同じ相手へ渡るが、Codex の記録は判定のために別の相手へ渡る。どの記録を渡すかは、開発者が置き場を指すことで選ぶ。

埋め込みの選択（#31）、記録を宿りの最初の記憶として取り込むこと（未決事項）、期待を自動で確定することは扱わない。出てはいけない記憶は下書きしない。混入は架空の評価セットと、人が禁止を書き足した件で測る。

## 入口の例

```console
$ uv run python -m yadori evals draft --from <記録の置き場> --out <手元の出力先>/real-recall.toml
記録: 28 セッション、中身のある発話 236 件（読めず飛ばしたファイル 0）
覚えさせる発話: 221 件
件: 15 件（後の発話が前の話題を指していそうなもの。すべて確認前）
  <手元の出力先>/real-recall.toml の各件を読み、残す件は confirmed = true にしてください

$ uv run python -m yadori measure --eval <手元の出力先>/real-recall.toml
測れません: 確認していない件が 15 件あります。各件を読み、残す件は confirmed = true にしてください
```

読み取れることは、何を取り出し、何を件にし、何が確認待ちかである。

## 手段の候補

- `IDEA-030-001`: 記録を時系列に並べて出すだけにし、人が全部読んで組を決める。読む量が千件を超え、続かない。採らない
- `IDEA-030-002`: 測られる側の埋め込みで前の発話との近さを出し、近い組を候補にする。埋め込みが既に見つけられる組しか候補に上がらず、見つけられない組（測りたい本命）が評価セットから消える。埋め込みを替える予定（#31）もあり、今の埋め込みで選んだ組は次の評価の偏った土台になる。採らない
- `IDEA-030-003`: 語の重なりで候補を出す。語が重なる組ばかりになり、言い換えの組が入らない。候補を出す手段としては採らない。ただし、組ごとに語の重なりの度合いを添えるのは軽く、人が言い換えの組を見つけやすくなる。添えるのは採る
- `IDEA-030-004`: 対話する道具（Claude Code、持ち主の定額契約）へ同じ作業場所の発話の並びを渡し、後の発話が前のどの話題を指しているかを判定させて組にする。測られる側とは別の仕組みで判定するため、埋め込みの得意な組へ偏らない。誤判定はあるが、人が最後に確かめる。呼ぶときは道具の文脈を外す（[ADR-016](../010_decisions/ADR-016-応対は対話する道具を通して作り、その道具の文脈を持ち込まない.md)）。作業場所ごとに置かれた指示が判定に混ざるためである。不利益は、呼び出しに時間がかかることと、定額契約の上限を消費し、上限に当たると宿りの応対まで使えなくなること。上限に当たれば下書きを書かずに断る。採る
- `IDEA-030-005`: 組は同じ作業場所の中だけで探す。人が話題を戻すのは主に同じ仕事の中で起きる。候補が絞れ、道具の呼び出しも減る。採る
- `IDEA-030-006`: 期待を自動で確定してそのまま測る。判定した側の癖がそのまま評価セットになり、測る側と測られる側の区別が曖昧になる。採らない

## 要件とシステムテスト

| 要件と根拠 | 必要な振る舞い |
|---|---|
| `SPEC-030-001`（`AC-018`）記録から一往復を取り出す | 対話する道具の記録の置き場を受け取り、利用者の発話と直後の返事を一往復として、記録された時刻の順に並べる。Claude Code と Codex の記録を読める。道具の命令、貼り付けた出力、画像だけの発話、中身のある語を持たない短い発話、「それ」「あれ」のように指す語だけの発話、話した言葉とは思えない長い発話（貼り付けた資料）は除く。どの作業場所の記録かを一往復ごとに持つ。同じ文言の発話が置き場全体で繰り返されるときは最初の一つだけを残す（測る側は文言で照合するため）。読めない記録のファイルは飛ばし、飛ばした数を結果に含める。置き場が無い、または一往復を一件も取り出せないときは、何も書かずに理由を返す |
| `SPEC-030-002`（`AC-018`）前の話題を指す組を候補にする | 同じ作業場所の中で、後の発話が前のどの発話の話題を指しているかを判定し、後の発話と前の発話の組を出す。組は後の発話を件、前の発話を期待とする一件になる。判定に、測られる側の埋め込みを使わない。埋め込みが導入されていない状態でも下書きは作れる。組にした後の発話は覚えさせる側から外す。一つの発話が件と期待の両方になるときは件にせず、期待として残す。同じセッションで既定の直近往復数以内の前の発話を指す組は、実際の会話では直近が渡す範囲なので件にしない。件を外した後に覚えさせる側へ残る並びの末尾から、既定の直近往復数の範囲に期待がある組は、測れないため候補から外す。期待が一つも残らない件は出さない（その発話は覚えさせる側にも戻さない。戻すと並びの末尾が動き、直近の判定がずれる）。件の期待ごとに、件と期待の語の重なりの度合いを添える。判定のために発話は対話する道具へ渡る。渡る相手は入口の使い方に書かれ、実行する前に読める。一つの後の発話が複数の前の発話を指すときは、期待を複数持つ一件にまとめる。判定する道具を呼べない、途中で失敗した、利用の上限に当たった、または渡した並びが大きすぎて受け付けられなかったときは、下書きを書かずに理由を返す。大きすぎたときの理由には、置き場を絞って指し直せることを含める。件が一つも出なければ、何も書かずに理由を返す |
| `SPEC-030-003`（`AC-018`）確かめていない件は測れない | 下書きは測る入口が読める形で出る。下書きの各件は、確認前であることが分かる印を件ごとに持つ。確認前の印を持つ件が一件でもあれば、一件も測らずに件数と理由を返す。印を持たない件は確認済みとして扱う。今までの架空の評価セットと手書きのものは印を持たないため、今までどおり測れる。やりとりどうし、または件どうしで名前が重なる評価セットは、一件も測らずに理由を返す。人は確認のついでに、出てはいけない記憶を件へ書き足せる |
| `SPEC-030-004`（`AC-018`）原文は手元に留まる | 出力先がリポジトリの配下、またはディレクトリなら、何も書かずに理由を返す。出力先に既にファイルがあれば、上書きせずに理由を返す。人の確認を消さないためである。下書きに書く発話と返事は記録の原文であり、言い換えない |

### 個々のシステムテスト

記録は架空の会話で作る。利用者の実際の記録を使わない。判定する道具は、決まった答えを返すものに差し替えて確かめる。本物の記録の形と、道具の判定の質は、それぞれ契約テストと手動確認で確かめる。

| テスト | 対応 | 観点 | 入力 | 期待する結果 |
|---|---|---|---|---|
| `ST-030-001` | `SPEC-030-001` | 中身のある一往復だけが時刻順に並ぶ | Claude Code の形と Codex の形で書いた架空の記録を置き場に置く。中身のある発話のほかに、道具の命令、貼り付けた出力、画像だけの発話、短い相槌、指す語だけの発話、資料を貼り付けた長い発話、同じ文言の発話の繰り返し、途中で切れた記録のファイルを混ぜる。次に、空の置き場と無い置き場を指す | 中身のある発話だけが、返事と対になって時刻順に並ぶ。二つの形の記録がどちらも読まれる。除いたものは一つも現れず、同じ文言は最初の一つだけ残る。切れたファイルは飛ばされ、飛ばした数が結果に出る。空と無い置き場では何も書かれず理由が返る |
| `ST-030-002` | `SPEC-030-002` | どの発話が件になり、どれが覚えさせる側に残るか（表駆動） | 判定を固定した道具で、次の発話を混ぜた架空の記録から下書きを作る。前の話題を別の言い方で指す発話。語も意味も遠いが道具が「指す」と答える発話。指さない発話。別の作業場所で同じ話題を指す発話。A→B→C と連鎖する三つの発話。同じセッションで直前の発話を指す発話。件を外す前は直近の外だが、外した後の並びでは末尾の直近に入る期待を持つ発話 | 指すと判定された発話は件になり、期待に前の発話が入る。指さない発話は覚えさせる側に残る。別の作業場所の発話は組にならない。連鎖の真ん中は期待として残り件にならない。同じセッションで直前の発話を指す組は出ない。外した後の並びで直近に入る組は出ない。件の期待ごとに語の重なりの度合いが添う |
| `ST-030-007` | `SPEC-030-002` | 埋め込みが無くても作れる | 埋め込みの道具を取り除いた状態で、判定を固定した道具で下書きを作る | 下書きが作れる。埋め込みが無いという理由で断られない |
| `ST-030-008` | `SPEC-030-002` | 判定が続かなければ何も書かない | 判定する道具を、呼べないもの、途中で失敗するもの、利用の上限に当たったと返すもの、大きすぎて受け付けないと返すものにそれぞれ差し替えて下書きを作る | いずれも下書きは書かれず、理由が返る。大きすぎたときの理由に、置き場を絞って指し直せることが含まれる |
| `ST-030-003` | `SPEC-030-003` | 確かめていない件があると測れない | `ST-030-002` で作った下書きをそのまま測る。次に全件を確認済みにして測る。次に印を持たない件を手で足して測る。次に印を持たない架空の評価セットを測る。次に二つの件に同じ名前を付けて測り、次に二つのやりとりに同じ名前を付けて測る | 一つ目は一件も測らず、確認していない件数と理由が返る。最後の二つは名前の重なりを理由に一件も測らない。残りは件ごとの結果が出る |
| `ST-030-004` | `SPEC-030-004` `SPEC-030-002` | リポジトリの中へは書かず、確認を上書きせず、何が起きたかが画面で読める | 出力先にリポジトリの配下を指す。次にディレクトリを指す。次に手元の置き場を指す。次に同じ手元の置き場へもう一度作る。あわせて入口の使い方を読む | 一つ目と二つ目は何も書かれず理由が返る。三つ目は下書きが書かれ、発話と返事が記録の原文と一致し、画面に読んだセッションの数、中身のある発話の数、飛ばしたファイルの数、覚えさせる発話の数、件の数と、全件が確認前である促しが出る。四つ目は上書きされず理由が返る。使い方に、どの記録が判定のためにどの相手へ渡るかが書かれている |
| `ST-030-005` | `SPEC-030-001` | 本物の記録の形が変わっていない（契約テスト） | 手元にある本物の記録の置き場を指して取り出す。通常の実行から分ける | Claude Code と Codex の記録からそれぞれ一往復以上が取り出せ、どちらの一往復も作業場所を持つ。件数だけを見て、発話は出力しない |
| `ST-030-006` | `SPEC-030-002` | 道具の判定が人の目に耐える（手動確認） | 本物の記録から作った下書きの件から無作為に二十件を選び、人が読む | 期待のどれかが妥当と判断できた件の割合と数を PR に書く。発話は引用しない。半分に届かなければ、判定のさせ方を見直してから実装を閉じる |

## 設計と結合テスト

### 設計判断

| 設計判断 | 実現する要件 | 構造と責務 |
|---|---|---|
| `AD-030-001` 記録の読み手は形式ごとに外側へ置き、記録の一往復は形式を知らない | `SPEC-030-001` | Claude Code と Codex の記録は形が違い、こちらの都合では変わらない。形式ごとの読み手を adapter に一つずつ置き、どちらも「発話、返事、時刻、作業場所」だけを持つ同じ形の記録の一往復を返す。各読み手はファイルの先頭行の項目で自分の形式かを答える。どの読み手も答えなかったファイルと、答えた読み手が途中で読めない行に当たったファイルを飛ばし、飛ばした数を数えるのは束ねる手順である。形式が分かって全行読めたものだけを使う。道具の命令、貼り付け、画像だけの発話、道具が子エージェントへ渡した指示のような形式に依る雑音は読み手が除く。道具の結果は利用者の発話の形で記録されるが発話ではないので、返事はそれを越えて次の本物の発話の手前まで読む。返事が記録に無い一往復は返事を空にし、評価セットの読み手も空の返事を読める。短い相槌や指す語だけの発話のような、形式に依らない「中身の無さ」は、記録の一往復の値が自分で答え、手順がそれを使って除く。読み手はこの規則を知らない |
| `AD-030-002` 判定は口として受け取り、下書きを作る手順は埋め込みを受け取れない | `SPEC-030-002` | 判定の口を domain に置く。渡すものは一つの作業場所の記録の一往復の並び、返すものはその並びの中の「後の発話と、それが指す前の発話」の組の集まりである。下書きを作る手順（usecase）は判定の口、読み手、書き手を受け取り、埋め込みの口は受け取らない。持たなければ使えないため、使っていないことが構造で保証される。判定は作業場所ごとに一度呼び、分けない。分けると組を探せる範囲が変わり要件が変わるため、道具が受け付けない大きさなら断る。実装は adapter に置き、対話する道具を文脈を外して呼ぶ。道具へ送るのは発話の文章（改行は潰す）と並びの番号だけで、返事、時刻、作業場所は送らない。貼り付けた資料は発話ではないので手前で除かれており、一つの作業場所の発話を一度に送るのが総量ではもっとも安い（各発話を一度しか送らない）（[ADR-017](../010_decisions/ADR-017-実際の会話の記録を判定のために対話する道具へ渡す.md)）。道具の呼び方（文脈を外す引数、待ち時間、返事の取り出し）は声と同じ一つの部品にし、声と判定はそれへ渡す文章と待ち時間だけが違う。呼び方が二箇所にあると、道具が変わったとき片方だけ直る。呼べない、途中で失敗、上限に当たった、大きすぎて受け付けられなかった、返事の形が違う、返事が範囲外や向き違いの番号を指した、のいずれも判定の実装が下書きの失敗（`CannotDraft`）として返し、usecase はそれを握らない。大きさは送る前に判定せず、道具の失敗として受ける |
| `AD-030-003` 組の整合は判定の後に手順が解き、測る側と同じ規則で読めることを確かめてから書く | `SPEC-030-001` `SPEC-030-002` | 複数の読み手の結果を束ねた後、置き場全体で同じ文言の発話を最初の一つに絞るのは手順の責務である。判定の結果もそのまま下書きにしない。一つの後の発話が指す前の発話が複数なら期待を複数持つ一件にまとめる、次に、同じセッションで直近往復数以内の前の発話を指す組を外す、次に、件と期待の両方になる発話は期待に残す、次に、件を外した後に残る並びの末尾から既定の直近往復数（`HowToRecall` の既定）に期待がある組を外す、期待が一つも残らない件を落とす、の順で手順が解く。語の重なりの度合いは domain が隣り合う文字二つの並びの共有で自前に求め、件に期待の名前ごとの値として書く。人が読む手掛かりであり、測る側は読まない。索引を作る文字の埋め込みは差し替えの対象なので縛らない。やりとりと件の名前は手順が連番で付け、重ならない。解いた結果を、測る側が読むのと同じ評価セットの形（`RecallEval`）に組み、評価セットの値自身が答える「指す先が揃い、期待と禁止が同じやりとりを指さず、名前が重なっていないか」を通してから書く。指す先と期待・禁止の規則は今 `Measuring` が持っている確認を評価セットの値へ移したもので、やりとりどうし・件どうしの名前の重なりはここで新しく足す。測る側もそれを呼ぶ。確認前の件を断る判定はここでは通さない。下書きは定義上すべて確認前だからである |
| `AD-030-004` 確認前の印は件が持つ値であり、断るのは測る側の独立した一段 | `SPEC-030-003` | 件（`Case`）に確認済みかどうかの値を足す。欄が無ければ確認済み。下書きの書き手は全件を確認前として書く。測る手順（`Measuring`）は、指す先を確かめる段とは別の名前を持つ段で確認前の件を数え、一件でもあれば `CannotMeasure` で断る。読み手（`EvalFile`）はこの欄を読むだけで判断しない。判断が測る側の一箇所に置かれるため、下書きから作った評価セットも手書きの評価セットも同じ入口で同じ規則を通る |
| `AD-030-005` 書き手が置き場の境界を守り、書くのは手順の最後の一段だけ | `SPEC-030-004` | 下書きの書き手は adapter に置き、出力先がリポジトリ（`.git` を持つディレクトリ）の配下か、既にファイルがあるか、ディレクトリを指しているかを書く前に確かめ、いずれも `CannotDraft` で断る。出力先の不備は一つの文面の系列にまとまる。usecase は書き手を最後に一度だけ呼ぶため、読み取りと判定の途中で失敗しても何も書かれない。発話と返事は記録の一往復の値をそのまま書き、書き手は文章を変えない |
