# INC-030 実際の会話の記録から評価セットの下書きを作る

| 項目 | 内容 |
|---|---|
| Issue | #30 実際の会話の記録から評価セットの下書きを作れるようにする |
| PR | [#35](https://github.com/yadori-dev/yadori/pull/35) |
| 選んだ受入基準 | `AC-018` 記録から評価セットの下書きが出る |

## 体験の変化

保守する開発者は、対話する道具が手元に残した記録のディレクトリを指す。中身のある発話が一往復ずつ時刻の順に並び、後の発話が前の話題を指していそうな問が、評価セットの下書きとして手元に出る。問は同じ作業場所（同じディレクトリで動いた記録）の中だけで探す。問の期待ごとに語の重なりの度合いが添うため、言い換えの問を見つけやすい。開発者は問ごとに期待が妥当かを読み、残すか消すかを決める。確かめていない問が残ったままでは測れない。確かめた下書きは、`INC-018` の仕組みでそのまま測れる。

千を超えるセッションを人が読んで数十問を書き写していた作業が、読んで決めるところだけになる。

会話の原文は手元に留まる。出力先にリポジトリの中を指すと断る。判定のために対話する道具（Claude Code）へ渡るのは、後の発話と、宿りの思い出す仕組みが引いた前の発話の候補（数件）だけである。作業場所の発話を丸ごと渡すことはしない。宿りは必要な記憶だけを渡すための道具であり、その周辺の道具も同じ前提で作る。Claude Code の記録は普段と同じ相手へ渡るが、Codex の記録は判定のために別の相手へ渡る。どの記録を渡すかは、開発者がディレクトリを指すことで選ぶ。

候補は宿りの思い出す仕組み（文を数字に変えて意味の近さで探す。測られる側と同じもの）で引く。そのため、この仕組みが拾えない組（緩めた下限を下回る組、件数の上限から外れた組）は候補に上がらず、下書きにも出ない。この盲点は人が手で足して補う。直近往復数以内の前の発話を指す組も候補に上がらないが、これは盲点ではなく、直近が常に渡るため測れない組であり、手で足してはいけない（`ADR-015`）。画面と使い方に両方を書く。どの埋め込みとどの条件で引いた下書きかも画面と下書きに残す。埋め込みを替えたら引き直す。

埋め込みの選択（#31）、記録を宿りの最初の記憶として取り込むこと（未決事項）、期待を自動で確定することは扱わない。出てはいけない記憶は下書きしない。混入は架空の評価セットと、人が禁止を書き足した問で測る。

## 入口の例

```console
$ uv run python -m yadori evals draft --from <記録のディレクトリ> --out <手元の出力先>/real-recall.toml
候補を引いた 埋め込み: paraphrase-multilingual-MiniLM-L12-v2（fastembed-0.8.0） / 条件: 直近6往復・候補10件・下限0.3 / 判定: opus
記録: 28 セッション、中身のある発話 151 件（読めず飛ばしたファイル 0）
覚えさせる発話: 106 件
問: 44 問（後の発話が前の話題を指していそうなもの。すべて確認前）
  --out の各問を読み、残す問は confirmed = true にしてください
  候補は思い出す仕組みが引いたものだけです。拾えなかった組（下限を下回る、件数の上限から外れた）は手で足せます。直近の範囲の組は測れないので足しません

$ uv run python -m yadori measure --eval <手元の出力先>/real-recall.toml
測れません: 確認していない問が 44 問あります。各問を読み、残す問は confirmed = true にしてください
```

読み取れることは、何で候補を引き、何を取り出し、何を問にし、何が確認待ちで、何が入っていないかである。

## 手段の候補

- `IDEA-030-001`: 記録を時系列に並べて出すだけにし、人が全部読んで組を決める。読む量が千件を超え、続かない。採らない
- `IDEA-030-002`: 宿りの思い出す仕組み（測られる側と同じ埋め込み）で、後の発話ごとに前の発話の候補を引く。下限を普段よりかなり緩め、件数も多めに取る。この仕組みが拾えない組は候補に上がらず下書きから消えるが、その盲点は人が手で足す。この下書きで埋め込みや下限を比べると、引いた側の埋め込みに有利に偏る（`ADR-017` の不利益）。代わりに判定へ渡すのは一つの発話と数件の候補だけで済み、作業場所の発話を丸ごと渡さない。採る
- `IDEA-030-003`: 語の重なりで候補を出す。語が重なる組ばかりになり、言い換えの組が入らない。候補を出す手段としては採らない。ただし、組ごとに語の重なりの度合いを添えるのは軽く、人が言い換えの組を見つけやすくなる。添えるのは採る
- `IDEA-030-004`: 対話する道具（Claude Code、持ち主の定額契約）へ、後の発話と `IDEA-030-002` で引いた候補だけを渡し、候補のうちどれが同じ話題かを判定させて組にする。候補は意味が近いと言われただけなので、話題が同じかは別の頭で決める。渡すものが小さいため、いくつかの発話とそれぞれの候補をまとめて一度に渡せる。誤判定はあるが、人が最後に確かめる。呼ぶときは道具の文脈を外す（[ADR-016](../010_decisions/ADR-016-応対は対話する道具を通して作り、その道具の文脈を持ち込まない.md)）。作業場所ごとに置かれた指示が判定に混ざるためである。不利益は、呼び出しの回数と時間、定額契約の上限を消費すること。上限に当たれば下書きを書かずに断る。採る
- `IDEA-030-007`: 作業場所の発話を丸ごと一度に対話する道具へ渡し、組を全部挙げさせる。実装して確かめたところ、一つの作業場所で数百発話、十万トークン級になり、宿りの前提（必要な記憶だけを渡す）と逆で、繰り返し使える道具にならない。採らない
- `IDEA-030-005`: 組は同じ作業場所の中だけで探す。人が話題を戻すのは主に同じ仕事の中で起きる。候補が絞れ、道具の呼び出しも減る。採る
- `IDEA-030-006`: 期待を自動で確定してそのまま測る。判定した側の癖がそのまま評価セットになり、測る側と測られる側の区別が曖昧になる。採らない

## 要件とシステムテスト

| 要件と根拠 | 必要な振る舞い |
|---|---|
| `SPEC-030-001`（`AC-018`）記録から一往復を取り出す | 対話する道具の記録のディレクトリを受け取り、利用者の発話と直後の返事を一往復として、記録された時刻の順に並べる。Claude Code と Codex の記録を読める。道具の命令、貼り付けた出力、画像だけの発話、中身のある語を持たない短い発話、「それ」「あれ」のように指す語だけの発話は除く。どの作業場所の、どのセッション（対話する道具を起こしてから終えるまで）の記録かを一往復ごとに持つ。同じ文言の発話が指したディレクトリ全体で繰り返されるときは最初の一つだけを残す（測る側は文言で照合するため）。読めない記録のファイルは飛ばし、どのファイルを飛ばしたかを結果に含める（画面は数を出す）。ディレクトリが無い、または一往復を一件も取り出せないときは、何も書かずに理由を返す |
| `SPEC-030-002`（`AC-018`）前の話題を指す組を候補にする | 同じ作業場所の中で、後の発話ごとに、宿りの思い出す仕組みで前の発話の候補を引く。候補のうちどれが同じ話題かを判定し、後の発話と前の発話の組を出す。組は後の発話を問、前の発話を期待とする一問になる。判定へ渡すのは後の発話とその候補だけで、作業場所の発話を丸ごと渡さない。候補に上がらなかった組は下書きに出ない。組にした後の発話は覚えさせる側から外す。一つの発話が問と期待の両方になるときは問にせず、期待として残す。作業場所の記憶の並びで既定の直近往復数以内にある前の発話は、思い出す手順が直近として渡すため候補に入らない。問を外した後に覚えさせる側へ残る並びの末尾から、既定の直近往復数の範囲に期待がある組は、測れないため候補から外す。期待が一つも残らない問は出さず、その発話は覚えさせる側へ戻す（直近を数える並びは戻す前のもので、戻した後に数え直さない）。問の期待ごとに、問と期待の語の重なりの度合いを添える。判定のために発話と候補は対話する道具へ渡る。渡る相手は入口の使い方に書かれ、実行する前に読める。一つの後の発話が複数の前の発話を指すときは、期待を複数持つ一問にまとめる。判定する道具を呼べない、途中で失敗した、利用の上限に当たった、または渡したものを受け付けなかったときは、下書きを書かずに理由を返す。意味を見る埋め込みを使えないときも、何も書かずに理由を返す。問が一つも出なければ、何も書かずに理由を返す |
| `SPEC-030-003`（`AC-018`）確かめていない問は測れない | 下書きは測る入口が読める形で出る。下書きの各問は、確認前であることが分かる印を問ごとに持つ。確認前の印を持つ問が一問でもあれば、一問も測らずに件数と理由を返す。印を持たない問は確認済みとして扱う。問が一問も無い評価セットは測れない。今までの架空の評価セットと手書きのものは印を持たないため、今までどおり測れる。やりとりどうし、または問どうしで名前が重なる評価セットは、一問も測らずに理由を返す。人は確認のついでに、出てはいけない記憶を問へ書き足せる |
| `SPEC-030-004`（`AC-018`）原文は手元に留まる | 出力先がリポジトリの配下、またはディレクトリなら、記録を読まず、判定へ何も渡さずに、何も書かずに理由を返す。出力先に既にファイルがあれば、追記（`--append`）でない限り、上書きせずに理由を返す。人の確認を消さないためである。下書きに書く発話と返事は記録の原文であり、言い換えない |

### 個々のシステムテスト

記録は架空の会話で作る。利用者の実際の記録を使わない。判定する道具は、決まった答えを返すものに差し替えて確かめる。本物の記録の形と、道具の判定の質は、それぞれ契約テストと手動確認で確かめる。

| テスト | 対応 | 観点 | 入力 | 期待する結果 |
|---|---|---|---|---|
| `ST-030-001` | `SPEC-030-001` | 中身のある一往復だけが時刻順に並ぶ | Claude Code の形と Codex の形で書いた架空の記録をディレクトリに置く。中身のある発話のほかに、道具の命令、貼り付けた出力、画像だけの発話、短い相槌、指す語だけの発話、同じ文言の発話の繰り返し、途中で切れた記録のファイルを混ぜる。次に、空のディレクトリと無いディレクトリを指す | 中身のある発話だけが、返事と対になって時刻順に並ぶ。二つの形の記録がどちらも読まれる。除いたものは一つも現れず、同じ文言は最初の一つだけ残る。切れたファイルは飛ばされ、飛ばしたファイルが結果に出る（画面は数）。空と無いディレクトリでは何も書かれず理由が返る |
| `ST-030-002` | `SPEC-030-002` | どの発話が問になり、どれが覚えさせる側に残るか（表駆動） | 文字の埋め込み（決まった値を返す）と下書き用の条件で候補を引き、判定を固定した道具で、次の発話を混ぜた架空の記録から下書きを作る。候補に上がる発話は前の発話と文字を共有させ、上がらない発話は共有させない。前の話題を指す発話。候補には上がるが話題が違うため道具が「指さない」と答える発話。候補が一つも上がらない発話。別の作業場所で同じ話題を指す発話。A→B→C と連鎖する三つの発話。記憶の並びで直前にある発話を指す発話。問を外す前は直近の外だが、外した後の並びでは末尾の直近に入る期待を持つ発話 | 指すと判定された発話は問になり、期待に前の発話が入る。候補に上がっても指さないと判定された発話と、候補が無い発話は覚えさせる側に残る。別の作業場所の発話は組にならない。連鎖の真ん中は期待として残り問にならない。直近往復数以内の前の発話を指す組は出ない。外した後の並びで直近に入る組は出ず、その発話は覚えさせる側に残る。問の期待ごとに語の重なりの度合いが添う |
| `ST-030-008` | `SPEC-030-002` | 判定が続かなければ何も書かない | 判定する道具を、呼べないもの、途中で失敗するもの、利用の上限に当たったと返すもの、受け付けないと返すものにそれぞれ差し替えて下書きを作る。次に、意味を見る埋め込みが使えない状態で下書きを作る。次に、候補は出るが判定がどれも指さないと答える道具で下書きを作る | いずれも下書きは書かれず、理由が返る。埋め込みが使えないときの理由から、何を導入すればよいかが分かる。最後は問が一つも出ないことが理由に書かれる |
| `ST-030-003` | `SPEC-030-003` | 確かめていない問があると測れない | `ST-030-002` で作った下書きをそのまま測る。次に全問を確認済みにして測る。次に印を持たない問を手で足して測る。次に印を持たない架空の評価セットを測る。次に二つの問に同じ名前を付けて測り、次に二つのやりとりに同じ名前を付けて測る | 一つ目は一問も測らず、確認していない件数と理由が返る。最後の二つは名前の重なりを理由に一問も測らない。残りは問ごとの結果が出る |
| `ST-030-004` | `SPEC-030-004` `SPEC-030-002` | リポジトリの中へは書かず、確認を上書きせず、何が起きたかが画面で読める | 出力先にリポジトリの配下を指す。次にディレクトリを指す。次に手元のディレクトリを指す。次に同じ手元のディレクトリへもう一度作る。あわせて入口の使い方を読む | 一つ目と二つ目は何も書かれず、記録を読まず判定へ何も渡さずに理由が返る。三つ目は下書きが書かれ、発話と返事が記録の原文と一致し、画面に、候補を引いた埋め込み（AIモデルの名前と道具の名前と版）と条件と判定の AIモデル、読んだセッションの数、中身のある発話の数、飛ばしたファイルの数、覚えさせる発話の数、問の数と、全問が確認前である促し、拾えなかった組（下限を下回るもの、件数の上限から外れたもの）は手で足せて直近の範囲の組は足さないことの断りが出る。下書きの `[covered]` の表にも埋め込み（AIモデルの名前と道具の名前と版）と条件と判定の AIモデルが残る。四つ目は上書きされず理由が返る。使い方に、どの記録が判定のためにどの相手へ渡るかが書かれている |
| `ST-030-005` | `SPEC-030-001` | 本物の記録の形が変わっていない（契約テスト） | 手元にある本物の記録のディレクトリを指して取り出す。通常の実行から分ける | Claude Code と Codex の記録からそれぞれ一往復以上が取り出せ、どちらの一往復も作業場所とセッションを持つ。件数だけを見て、発話は出力しない |
| `ST-030-006` | `SPEC-030-002` | 道具の判定が人の目に耐える（手動確認） | 本物の記録から作った下書きの問から無作為に二十問を選び、人が読む | 期待のどれかが妥当と判断できた問の割合と数を PR に書く。発話は引用しない。半分に届かなければ、判定のさせ方を見直してから実装を閉じる |

## 設計と結合テスト

### 設計判断

| 設計判断 | 実現する要件 | 構造と責務 |
|---|---|---|
| `AD-030-001` 記録の読み手は形式ごとに外側へ置き、記録の一往復は形式を知らない | `SPEC-030-001` | Claude Code と Codex の記録は形が違い、こちらの都合では変わらない。形式ごとの読み手を adapter に一つずつ置き、どちらも「発話、返事、時刻、作業場所、セッション」だけを持つ同じ形の記録の一往復を返す。各読み手はファイルの先頭行の項目で自分の形式かを答える。どの読み手も答えなかったファイルと、答えた読み手が途中で読めない行に当たったファイルを飛ばし、どのファイルを飛ばしたかを集めるのは束ねる手順である（画面は数を出す）。形式が分かって全行読めたものだけを使う。道具の命令や貼り付け、画像だけの発話、道具が子エージェントへ渡した指示のような形式に依る雑音は読み手が除く。道具の結果は利用者の発話の形で記録されるが発話ではないので、返事はそれを越えて次の本物の発話の手前まで読む。返事が記録に無い一往復は返事を空にし、評価セットの読み手も空の返事を読める。短い相槌や指す語だけの発話、話した言葉とは思えない長い発話（貼り付けた資料）のような、形式に依らない「中身の無さ」は、記録の一往復の値が自分で答え、手順がそれを使って除く。読み手はこの規則を知らない |
| `AD-030-002` 候補は思い出す手順で引き、判定は口として受け取る | `SPEC-030-002` | 下書きを作る手順（usecase）は、作業場所ごとに使い捨ての記憶を組み、記録の一往復を時刻の順に、まずその発話で思い出して候補を得てから、覚えさせる。思い出してから覚える順にするのは、その発話自身が直近に入って直近の窓が一つずれるのを避けるためである。思い出す手順は会話と同じ `Conversation.recall` を呼び、下書きのためだけの別経路を作らない（`AD-018-001` と同じ理由）。思い出し方の値は下書き用に緩めたもの（下限を低く、件数を多く）を渡す。手順は判定の口、読み手、下書きの置き場、埋め込みの口、記憶の作り方を受け取る。判定の口は domain に置き、渡すものは「後の発話と、その候補の並び」をいくつかまとめたもの、返すものは後の発話ごとに同じ話題と判定した候補の番号である。一度に渡す発話の数と、発話ごとの候補の数には上限を置き、渡すものの大きさは手順の側で抑える。実装は adapter に置き、対話する道具を文脈を外して呼ぶ。道具へ送るのは後の発話と候補の発話の文章（改行は潰す）と番号だけで、返事、時刻、作業場所は送らない（[ADR-017](../010_decisions/ADR-017-実際の会話の記録を判定のために対話する道具へ渡す.md)）。道具の呼び方（文脈を外す引数、待ち時間、返事の取り出し）は声と同じ一つの部品にし、声と判定はそれへ渡す文章と待ち時間だけが違う。呼び方が二箇所にあると、道具が変わったとき片方だけ直る。呼べない、途中で失敗、上限に当たった、受け付けられなかった、返事の形が違う、返事が候補に無い番号を指した、のいずれも判定の実装が下書きの失敗（`CannotDraft`）として返し、usecase はそれを握らない。埋め込みが使えない失敗（`EmbeddingsUnavailable`）は思い出す手順から伝わり、usecase はこれも握らない |
| `AD-030-003` 組の整合は判定の後に手順が解き、測る側と同じ規則で読めることを確かめてから書く | `SPEC-030-001` `SPEC-030-002` | 複数の読み手の結果を束ねた後、指したディレクトリ全体で同じ文言の発話を最初の一つに絞るのは手順の責務である。直近往復数以内の前の発話は、思い出す手順が直近として渡すため候補に入らない。判定の結果もそのまま下書きにしない。一つの後の発話が指す前の発話が複数なら期待を複数持つ一問にまとめる、次に、問と期待の両方になる発話は期待に残す、次に、問を外した後に残る並びの末尾から既定の直近往復数（`HowToRecall` の既定）に期待がある組を外す、期待が一つも残らない問を落としてその発話は覚えさせる発話として並びに戻す（直近を数える並びは戻す前のもので、数え直さない）、の順で手順が解く。解いた結果が問ゼロなら手順が `CannotDraft` で断る。下書きの置き場で断らない。語の重なりの度合いは domain が隣り合う文字二つの並びの共有で自前に求め、問に期待の名前ごとの値として書く。人が読む手掛かりであり、測る側は読まない。インデックスを作る文字の埋め込みは差し替えの対象なので縛らない。やりとりと問の名前は手順が連番で付け、重ならない。解いた結果を、測る側が読むのと同じ評価セットの形（`RecallEval`）に組み、評価セットの値自身が答える「指す先が揃い、期待と禁止が同じやりとりを指さず、名前が重なっていないか」を通してから書く。指す先と期待・禁止の規則は今 `Measuring` が持っている確認を評価セットの値へ移したもので、やりとりどうし・問どうしの名前の重なりはここで新しく足す。測る側もそれを呼ぶ。確認前の問を断る判定はここでは通さない。下書きは定義上すべて確認前だからである |
| `AD-030-004` 確認前の印は問が持つ値であり、測れる形かを断るのは測る側の独立した一段 | `SPEC-030-003` | 問（`Case`）に確認済みかどうかの値を足す。欄が無ければ確認済み。下書きの置き場は全問を確認前として書く。測る手順（`Measuring`）は、指す先を確かめる段とは別の名前を持つ段で、確認前の問を数えて一問でもあれば `CannotMeasure` で断り、問が一問も無いときも同じ段で断る。読み手（`EvalFile`）はこの欄を読むだけで判断せず、問が一つも無くても読む。判断が測る側の一箇所に置かれるため、下書きから作った評価セットも手書きの評価セットも同じ入口で同じ規則を通る |

| `AD-030-006` 入口は二段の下位命令にし、手順は数を返し、伝えるのは infrastructure | `SPEC-030-001` `SPEC-030-004` | 入口は `evals draft` の二段の下位命令にする。測る（`measure`）と並ぶ評価セットの命令が増えるため、`evals` の下に置く。既存の `measure` はそのまま残す。手順は、読んだセッションの数、中身のある発話の数、飛ばしたファイル（パスの並び。画面は数を出す）、覚えさせる発話の数、問の数の五つを持つ値を返し（下書きの問は定義上すべて確認前なので、確認が要る数は別に持たない）、書くのと画面へ出すのは infrastructure（`Measure` と同じ形）。画面と下書きの `[covered]` の表に、候補を引いた埋め込み（AIモデルの名前と道具の名前と版）と条件と判定の AIモデルを書く。測るときと同じく、何で引いたかが無いと後から比べられない。拾えなかった組（下限を下回るもの、件数の上限から外れたもの）は手で足せること、直近の範囲の組は測れないので足さないことの断りも画面に出す。読んだセッションの数は、記録の一往復が持つセッションから求める。下書きの失敗（`CannotDraft`）と埋め込みが使えない失敗（`EmbeddingsUnavailable`）は infrastructure が受け、理由を標準エラーへ書いて 1 を返す。引数が足りない、または知らない引数があるときは、既存の入口と同じく使い方を標準エラーへ書いて 1 を返す。使い方には、どの記録が判定のためにどの相手へ渡るかを書く（[ADR-017](../010_decisions/ADR-017-実際の会話の記録を判定のために対話する道具へ渡す.md)） |
