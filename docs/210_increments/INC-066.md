# INC-066 Discord から宿りへ話しかけられる

| 項目 | 内容 |
|---|---|
| Issue | #66 Discord から宿りへ話しかけられるようにする |
| PR | [#67](https://github.com/yadori-dev/yadori/pull/67) |
| 選んだ受入基準 | `AC-003` 二つ以上の道具から続けて話しかけても、同じ相手として続く |

## 体験の変化

持ち主が自分の Discord から宿りへ直接話しかけると、宿り自身の言葉で返事が返る。返事を作っている間は、そう見えるようにする。端末で話した続きが Discord でも続き、Discord で話した続きが端末でも続く。覚えていることも、今の気持ちも性格も、同じ一人ぶんである（`AC-003`）。

薄く作る。受け取るのは持ち主本人からの直接の会話だけで、サーバーの部屋には出ない（[ADR-019](../010_decisions/ADR-019-Discordへはbotとして繋ぎトークンを持ち主の手元に置く.md)）。宿りの側から話しかけることはまだしない。動かし続けるのは持ち主の道具に任せる。返事を作るのは今までどおり手元の対話する道具で、提供元への鍵は要らない（[ADR-016](../010_decisions/ADR-016-応対は対話する道具を通して作り、その道具の文脈を持ち込まない.md)）。

端末と同じ一往復の手順（`Turn`）を通すため、気持ちの動きも夢の要点も自動でそのまま効く。この増分で新しく作るのは、話す場所を一つ足すことだけである。

## 入口の例

```console
$ cat ~/.yadori/discord.toml
token = "<Discord の bot のトークン>"
owner_id = 123456789012345678

$ uv run python -m yadori discord
（そら が Discord に居ます。終わるには Ctrl-C）

$ uv run python -m yadori discord   # トークンが無いとき
~/.yadori/discord.toml がありません。次の形で作ってください。
  token = "<Discord の bot のトークン>"
  owner_id = <自分のユーザーID>
```

## 手段の候補

- `IDEA-066-001`: 送るだけの仕掛け（webhook）で繋ぐ。受け取れないため、話しかけられて答えるという形が成り立たない。採らない（[ADR-019](../010_decisions/ADR-019-Discordへはbotとして繋ぎトークンを持ち主の手元に置く.md)）
- `IDEA-066-002`: 言葉が届くたびに外から起こす形にする。届いたことを知る手段が結局 bot なので、二度手間になる。採らない
- `IDEA-066-003`: bot として繋ぎ、持ち主からの直接の会話だけを受ける。**採る。** 受け取る仕組みは口として受け、実物の繋ぎは差し替えられるようにする

## 要件とシステムテスト

| 要件と根拠 | 必要な振る舞い |
|---|---|
| `SPEC-066-001`（`AC-003`）持ち主の直接の会話にだけ答える | Discord から届いた言葉のうち、持ち主本人からの直接の会話だけに答える。他の人の言葉、部屋での言葉、宿り自身の言葉には答えず、記憶も増やさない。答えるときは、返事を作っている間そう見えるようにする。答えない言葉では、そう見せる印も出さない |
| `SPEC-066-002`（`AC-003`）端末と同じ一往復を通り、状態が続く | 答えるときは端末と同じ一往復の手順を通る（思い出す・応対を作る・覚える）。Discord での往復は端末から見た直近のやりとりに現れ、気持ちの動きも同じ一つの並びに積まれる。逆も同じ。応対に混ぜる気持ちの印の行は Discord へ出さない |
| `SPEC-066-003`（`AC-003`）トークンは手元から読み、失敗の理由は手元に残す | トークン（その bot を見分けるための長い文字列）と持ち主のユーザーID は `YADORI_HOME/discord.toml` から読む。無い・欠けている・形が違う・書き方が壊れているときは、何をどう書けばよいかを含む理由を返して終わる。Discord へ繋げないときも理由を返して終わる。トークンは画面にも記録にも出さない。返事を作れないとき（対話する道具が応えない、埋め込みが使えない）は、Discord へは応対できないことだけを返し、理由は手元に書き、その往復は覚えない。長い返事は Discord が受け取れる長さに分けて送る |

### 個々のシステムテスト

実物の Discord へは繋がない。受け取る仕組みを差し替えて、届いた言葉と送った言葉だけを見る。

| テスト | 対応 | 観点 | 入力 | 期待する結果 |
|---|---|---|---|---|
| `ST-066-001` | `SPEC-066-001` | 誰の言葉に答えるか（表駆動） | 持ち主の直接の会話、他の人の直接の会話、部屋での持ち主の言葉、宿り自身の言葉、空の言葉、を届ける | 一つ目だけに返事が送られ、記憶が一件増える。残りは何も送らず、記憶も動きも増えない。考えている印は、答える言葉のときだけ立ち、答えない言葉では立たない |
| `ST-066-002` | `SPEC-066-002` | 端末と行き来しても同じ相手 | Discord で一往復し、続けて端末で一往復する。次に Discord でもう一度話しかける | 端末の応対に Discord での往復が直近として渡り、Discord の応対に端末での往復が渡る。気持ちの動きが一つの並びに三件積まれ、`state` で読める。Discord へ送られた文に気持ちの印の行が無い。名乗りは場所が組む |
| `ST-066-003` | `SPEC-066-003` | トークンと失敗の伝え方 | トークンのファイルが無い、欄が欠けている、ユーザーID が数でない、書き方が壊れている、で起こす。次に、応対を作れない声で話しかける。次に、二千字を超える返事を返す声で話しかける | 前の四つは理由が返って終わり、トークンは出力に現れない。応対を作れないときは Discord へ応対できないことだけが送られ、理由は手元にだけ残り、記憶は増えない。長い返事は複数に分かれ、合わせると元の文になる |

## 設計と結合テスト

### 設計判断

| 設計判断 | 実現する要件 | 構造と責務 |
|---|---|---|
| `AD-066-001` 話す場所を口にし、Discord の受け取りは差し替えられる形にする | `SPEC-066-001` `SPEC-066-003` | `adapter/place` に話す場所の口（`Place`。`listen()` だけを持つ）を置き、端末と Discord の両方がそれを満たす。Discord の場所（`DiscordPlace`）は、受け取る仕組みを口（`Gateway`。届いた言葉と考えている印の出し方を渡し、返した文を送る）で受け取り、実物の繋ぎ（`DiscordGateway`。外の道具を使う）と差し替えられるようにする。届いた言葉は値（`Heard`。文、誰から、直接の会話か）にして、外の道具の型を場所より内側へ出さない。**受け取るものは Discord へ申し込む段階で直接の会話だけに絞り**、サーバーの部屋の言葉がそもそも届かないようにする。そのうえで、答えるかどうか（持ち主本人か、直接の会話か、中身があるか）と、名乗りに何と言うかは場所が決め、繋ぎは判断しない |
| `AD-066-002` 起動は場所を受け取り、組み立ては一つのまま | `SPEC-066-002` | 起動（`Startup`）に、どの場所で待つかを渡せるようにする（既定は端末）。記憶を開き、宿りを住まわせ、一往復の手順を組み、インデックスを作り直すまでは今までと同じ手順で、最後に渡された場所で待つ。Discord のための別の起動を作らない。これにより、Discord も端末と同じ `Turn` を通り、気持ちと夢は何もしなくても効く。場所が繋げないとき（`CannotConnect`）は、起こせないときと同じく理由を書いて終わる |
| `AD-066-003` トークンは設定の読み手が扱い、外へ出さない | `SPEC-066-003` | `SettingsFile` に Discord の設定を読む口を足す（`discord()`。`YADORI_HOME/discord.toml` からトークンと持ち主のユーザーID）。無い・欠けている・形が違う・書き方が壊れているときは、宿りの設定と同じ失敗（`NotSettled`）で、何をどう書けばよいかを含めて返す。壊れた書き方の理由には書きかけの中身が入りうるため、道具の文言はそのまま添えない。トークンは値として持つだけで、画面にも記録にも出さない。読んだ設定を人が読む形にするときも伏せる |
| `AD-066-004` 待ち時間と失敗は場所が受け、外へ出す文は絞る | `SPEC-066-001` `SPEC-066-003` | 応対を作るのに時間がかかる（対話する道具を起こす）ため、Discord の場所は待っている間も他の言葉を取りこぼさないよう、一往復ずつ順に扱う。考えている印は、答えると決めて**順番が回ってきてから**立てる（待っている数だけ同じ印を送らないため）。返事が Discord の受け取れる長さ（二千字）を超えるときは、場所が分けて送る。分け方は改行の切れ目を優先し、無ければそのまま切る。応対を作れない失敗（`CannotSpeak`、`EmbeddingsUnavailable`）は覚えずに終わるが、**理由は手元にだけ書き、Discord へは応対できないことだけを返す**（理由には手元で動かしている道具の出力がそのまま入るため）。繋ぎの側で起きた失敗（送れない、覚えられない）も黙って落とさず手元へ書き、次の言葉を待つ |

### 個々の結合テスト

| テスト | 対応 | 観点 | 入力 | 期待する結果 |
|---|---|---|---|---|
| `IT-066-001` | `AD-066-001` | 場所が答えるかどうかを決め、繋ぎは判断しない | 差し替えの繋ぎから、持ち主・他の人・部屋・自分・空、の言葉を渡す | 返事が返るのは持ち主の直接の会話だけ。他は繋ぎへ何も渡らない。繋ぎは判断の材料（誰から、直接か）を渡すだけで、答えるかどうかを決めていない |
| `IT-066-002` | `AD-066-002` | 起動が場所を受け取り、同じ手順を通る | 差し替えの場所を渡して起動する。次に何も渡さずに起動する。次に、繋げない場所を渡して起動する | どちらもインデックスの作り直しまで同じ手順を通り、渡した場所へ届く前に宿りが住まわされ名乗りが書かれている。何も渡さなければ端末で待ち、端末の呼びかけが出る。繋げない場所では理由を書いて 1 で終わる |
| `IT-066-003` | `AD-066-003` | トークンの読み方と伏せ方（表駆動） | ファイルが無い、トークンが欠けている、ユーザーID が欠けている、ユーザーID が数でない、トークンが空、書き方が壊れている、の六通りで読む。次に正しい形で読む | 前の六つは `NotSettled` で、理由に書き方が含まれ、トークンは現れない。正しいときはトークンとユーザーID が読め、設定を人が読む形にしてもトークンが現れない |
| `IT-066-004` | `AD-066-004` | 分け方、順に扱うこと、失敗の返し方（表駆動） | 二千字ちょうど、超える（改行あり）、超える（改行なし）、の返事を返す声で話しかける。次に、時間のかかる声へ三つの言葉を同時に投げる。次に応対を作れない声、埋め込みが使えない声で話しかける | 二千字までは一つ。超えるときは複数に分かれ、合わせると元の文になり、どれも二千字を超えない。改行があればそこで切れる。同時に投げても応対は重ならず、入ったら出るまで次が入らない。失敗は Discord へ応対できないことだけが送られ、理由は手元に残り、記憶は増えない |
| `IT-066-005` | `AD-066-001` `AD-066-004` | 実物の discord.py への配線 | 繋ぐところ（`Client.run`）だけを差し替えて待たせ、部屋の言葉と直接の会話を渡す。次に送れない状態で渡す。次にトークンが違う状態で待たせる | 組み上がった繋ぎは直接の会話だけを受け取る形になっており（部屋の言葉は受け取らない、言葉の中身を読む特権の許可も要らない）、渡したトークンと警告の出し方で繋ごうとする。繋がったら名乗りが出る。部屋の言葉では何も送らず考えている印も出さない。直接の会話では印を出して答え、記憶が増える。送れないときは理由が手元へ出て止まらない。トークンが違えば繋げない理由が返り、トークンは含まれない |
