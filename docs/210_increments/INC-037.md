# INC-037 下書きに増えた記録の分だけを足す

| 項目 | 内容 |
|---|---|
| Issue | #37 評価セットの下書きに、増えた記録の分だけを足せるようにする |
| PR | 未作成 |
| 選んだ受入基準 | `AC-019` 追記で前回の問と確認が保たれ、増えた分だけが足される |

## 体験の変化

保守する開発者は、前に作った下書きと同じファイルを指して追記する。前回の範囲（どの時刻まで、どのディレクトリから読み、どのファイルを飛ばしたか）より後に増えた記録だけが読まれ、その発話だけが候補を引かれて判定へ渡り、新しい問が末尾に確認前として足される。前回の問とその確認（`confirmed`、消した問、書き足した禁止、変えた名前）は一字も変わらない。前回の範囲は下書きに残り、人が読め、次の追記はそこから読む。

記録が増えるたびに別のファイルへ作り直して確認を手で写す作業と、既に確かめた分の費用を二度払うことが無くなる。代わりに、前回の下書きに無い発話（前回落ちた発話、消した問）は追記で戻らない。取りこぼしが気になれば新しいファイルへ作り直す。

追記できるのは、この増分以降の道具が作った下書きだけである。前回の範囲を持たない下書き（この増分より前に作ったもの）には足せず、一度作り直す。埋め込みの名前と条件、判定に使う AIモデルが下書きの冒頭と違うとき、記録のディレクトリが前回と違うときも足さず、新しいファイルへ作り直すよう伝える。混ぜると何で引いた下書きか読めなくなる。手書きの評価セットにも足さない。

## 入口の例

```console
$ uv run python -m yadori evals draft --from <記録のディレクトリ> --out <手元>/real-recall.toml --append
候補を引いた 埋め込み: paraphrase-multilingual-MiniLM-L12-v2/fastembed-0.8.0 / 条件: 直近6往復・候補10件・下限0.3
前回の範囲: 2026-08-31 15:20 まで、<記録のディレクトリ>、飛ばしたファイル 0、28 セッション
前回の下書き: 覚えさせる発話 106 件、問 44 問
今回: 新しい記録 3 セッション、新しい発話 21 件（読めず飛ばしたファイル 0）、判定へ渡した発話 15 件、候補が無く渡さなかった発話 6 件
覚えさせる発話: +17 件
問: +4 問（すべて確認前）。前回の 44 問とその確認はそのまま
  <手元>/real-recall.toml の新しい問を読み、残す問は confirmed = true にしてください

$ uv run python -m yadori evals draft --from <記録のディレクトリ> --out <手元>/hand-written.toml --append
下書きを作れません: <手元>/hand-written.toml は前回の範囲を持たないので追記できません。この増分以降の道具で作り直してください
```

数値は増分の中で決める。読み取れることは、前回の範囲、今回何が増え、何を判定へ渡し、何が変わらなかったかである。

## 手段の候補

- `IDEA-037-001`: 判定の会話を対話する道具の継続（`--resume`）で続け、新しい問いだけを渡す。試したところ会話は続く。ただし今の判定は「後の発話と数件の候補」の小さな問いを十ずつ渡す独立した呼び出しで、前の会話を渡し直していない。継続で減るのは前置き（[ADR-016](../010_decisions/ADR-016-応対は対話する道具を通して作り、その道具の文脈を持ち込まない.md) の実測で三百語ほど）だけで、逆に会話を続けると前の問いが文脈に積み上がり、呼ぶたびの量は増える側である。会話の識別子を下書きへ残す仕組みと、応対は一往復ごとに新しく呼ぶ判断との線引きも要る。採らない。既に確かめた分の費用を二度払わないことは、増えた記録だけを判定することで満たす
- `IDEA-037-002`: 下書きに前回の範囲（読めた一往復の最大の時刻、読んだディレクトリ、飛ばしたファイル、セッション数）を残し、その時刻より後、または前回飛ばしたファイルの記録だけを新しい発話とする。採る
- `IDEA-037-003`: 前回のやりとりと問は読み込んでそのまま書き戻し、新しいやりとりと問を末尾に足す。使った番号の最後も下書きに残し、消された問の番号を使い回さない。採る
- `IDEA-037-004`: 候補を引く記憶は、前回の下書きにある覚えさせる発話と、今回の新しい発話だけで組む。記録は毎回全部読み直すが、それは前回の発話の作業場所と時刻を知るためで、下書きに無い発話（前回の問、人が消した問、期待が残らず落ちた発話）は記憶に入れない。判定へ渡すのは新しい発話だけにする。代償は三つ。記録の読み直しと埋め込みの作り直しは記録の総量に比例して伸びる（数百発話で数十秒の見込み。測っていない）。記録が消えたり移されたりすると前回と同じ候補の引き方にならない（ディレクトリが違えば断る）。途中で失敗すると新しい分の判定は捨てになる。採る
- `IDEA-037-005`: 追記は道具が作った下書きにだけ受け付け、埋め込みの名前と条件、判定の AIモデル、記録のディレクトリが前回と同じときだけにする。違うときは新しいファイルへ作り直す。判定の指示の書き方が変わったことは道具が見分けられないので、その場合は人が作り直す。採る

## 要件とシステムテスト

| 要件と根拠 | 必要な振る舞い |
|---|---|
| `SPEC-037-001`（`AC-019`）追記の対象と範囲 | `--append` で既にある下書きを指す。下書きは前回の範囲（読めた一往復の最大の時刻、読んだディレクトリ、読めず飛ばしたファイル、セッション数）と、何で候補を引き何で判定したか（埋め込みの名前と条件、判定の AIモデル）と、やりとりと問それぞれで使った名前の最後の番号を人が読める形で持つ。それを持たないファイルには何も変えずに理由を返す。埋め込みの名前か条件、判定の AIモデル、記録のディレクトリの集まり（順序は問わない）が今と違うときも何も変えずに理由を返し、新しいファイルへ作り直すよう伝える。新しい発話は、前回の時刻と同じかそれより後に記録された一往復と、前回飛ばしたファイルの一往復のうち、前回の発話と同じ文言のものを除いたものである |
| `SPEC-037-002`（`AC-019`）前回の問と確認を保つ | 前回のやりとりと問（名前、発話、返事、期待、禁止、確認の印、語の重なりの度合い、並び）は一字も変えずに残す。人が名前を変えた問、消した問、順序を変えた問もそのまま。新しいやりとりと問は末尾に足し、名前は前回使った最後の番号の次から付ける。消された問の番号は使い回さない。新しいやりとりは記録の時刻の順に並べて末尾に足す。前回飛ばしたファイル由来で前回の時刻より古い発話も末尾側に置くが、候補は記録の時刻で自分より前の発話からだけ引く。問を外した後に残る並びの末尾から既定の直近往復数の範囲に期待がある組は、前回と今回を合わせた並びで当て直して外す。追記した下書きは、全問を確認済みにすれば今までどおり測れる（指す先が揃い、名前が重ならない） |
| `SPEC-037-003`（`AC-019`）判定へは新しい発話だけ | 候補は、前回の下書きにある覚えさせる発話と今回の新しい発話（同じ作業場所）だけから引く。前回の問の発話、人が消した問の発話、前回落ちた発話は下書きに無いので候補にならない。判定の問いにするのは新しい発話だけで、前回の問の発話は渡さない。新しい発話が前回の覚えさせる発話を指す組は問になる。候補が無い新しい発話は判定へ渡さず、その数を画面に出す |
| `SPEC-037-004`（`AC-019`）何が起きたかを伝え、途中の失敗で変えない | 画面に、前回の範囲（時刻、ディレクトリ、飛ばしたファイルの数、セッション数）と前回の下書きから数えた覚えさせる発話の数と問の数、今回増えた記録の数と新しい発話の数、判定へ渡した発話の数と候補が無く渡さなかった発話の数、足した発話と問の数、前回の問と確認がそのままであることが出る。渡した数と渡さなかった数の和は新しい発話の数（同じ文言を除いた後）と一致する。新しい問が一つも無くても前回の範囲は更新して書き、問が増えなかったことを画面に出す（新しいファイルを作るときの「問がゼロなら書かない」「既にあるファイルには書かない」は追記には当てはめない）。判定、埋め込み、記録の読み取りが途中で失敗したときは、下書きは一字も変わらない |

### 個々のシステムテスト

記録は架空の会話で作る。候補は決まった値を返す文字の埋め込みと下書き用の条件で引き、判定は答えを固定したものに差し替える。

| テスト | 対応 | 観点 | 入力 | 期待する結果 |
|---|---|---|---|---|
| `ST-037-001` | `SPEC-037-002` | 前回の内容が保たれ、新しい問が末尾に足され、測れる | 一度作った下書きに、確認済みの問、消した問（最後の番号）、名前を変えた問、順序を変えたやりとり、禁止を書き足した問を人の手で混ぜる。次に記録を増やして（前回より後の時刻、新しいセッション）追記する。全問を確認済みにして測る | 前回のやりとりと問は一字も変わらない。新しいやりとりと問が末尾に足され、名前は消した問の番号を使い回さず次から続く。新しい問は確認前である。前回の発話と同じ文言の新しい発話は足されない。全問を確認済みにすると測れる。合わせた並びの末尾の直近に期待がある組は問にならない |
| `ST-037-002` | `SPEC-037-003` | 判定へ渡るのは新しい発話だけ | 渡されたものを記録する判定の口を差し込んで追記する。新しい発話に、前回の覚えさせる発話を指すもの、前回の問の発話や人が消した問の発話と同じ話題のもの、候補が一つも上がらないもの、前回の最大の時刻の発話と同じ文言のものを混ぜる | 判定の問いの発話はすべて新しい発話で、前回の問の発話や同じ文言の発話は含まれない。前回の問の発話と消した問の発話は候補にも上がらない。前回の覚えさせる発話を指す組が問になる。画面の「判定へ渡した発話」と「候補が無く渡さなかった発話」の和が新しい発話の数と一致する |
| `ST-037-003` | `SPEC-037-001` | 対象でないものには足さない（表駆動） | 手書きの評価セット、無いファイル、前回の範囲を持たない下書き、埋め込みの名前が違う下書き、条件（下限）だけが違う下書き、判定の AIモデルが違う下書き、記録のディレクトリを一つ足した追記、にそれぞれ追記する | いずれも何も変わらず、理由が返る。前回の範囲を持たないときは作り直しを、埋め込み・条件・AIモデル・ディレクトリが違うときは新しいファイルへ作り直すことを、理由が伝える |

## 設計と結合テスト

### 設計判断

| 設計判断 | 実現する要件 | 構造と責務 |
|---|---|---|
| `AD-037-001` 前回の範囲は下書きの中の `[drafted]` 表として道具が持ち、値は domain の `Covered` | `SPEC-037-001` | 下書きの冒頭、`within` の次に `[drafted]` の表を置き、読めた一往復の最大の時刻（`until`、記録の時刻を時差付きでそのまま）、読んだディレクトリ（`places`、絶対パスに解いた並び）、読めず飛ばしたファイル（`skipped`、絶対パスの並び。数ではなく、どのファイルかを残す。次の追記で読み直すために要る）、読んだセッションの数（`sessions`）、候補を引いた埋め込みの名前（`embedding`）と条件（`recent`、`limit`、`floor`）、判定の AIモデル（`judge`）、やりとりと問で使った名前の最後の番号（`last_exchange`、`last_case`）を書く。人が読める形であり、表の上に「道具が書く前回の範囲。追記はここから読む。人は変えない」と断る。今まで冒頭の注釈に書いていた「候補を引いた 埋め込みと条件」はこの表に移し、注釈からは外す（同じことを二箇所に書くと、片方だけ直る）。画面には今までどおり出す。domain にこの値 `Covered` を置き、今の条件と同じかを自分で答える（`Covered.differs_from(embedding, how, judge, places)`。違うところを文で返し、同じなら無し）。ディレクトリの集まりは順序を問わず比べる。判定の口（`Judge`）に名前（`name`）を足し、対話する道具で判定する実装は道具の呼び方が持つ AIモデルの名前を返す。埋め込みの口が名前を持つのと同じで、何で作ったかを下書きに残すにはこの名前が要る |
| `AD-037-002` 新しい発話は手順が前回の範囲と前回の下書きから選び、数は選んだ場で数える | `SPEC-037-001` `SPEC-037-004` | 下書きを作る手順（`Drafting`）に追記の入口（`append(places, out)`）を足す。記録は今までどおり全部読み直す（時刻の順、飛ばしたファイルはパスで集める）。新しい一往復は「時刻が前回の `until` と同じかそれより後」または「ファイルが前回の `skipped` にある」もの。そのうち中身のあるものに絞り、同じ文言を最初の一つにし、さらに前回の下書きにある発話（覚えさせる発話と問の発話の両方）と同じ文言のものを除く。除いた後の数が「新しい発話の数」で、判定へ渡した数と候補が無く渡さなかった数の和はこれに一致する。今回増えた記録のセッション数は、新しい一往復（中身で絞る前）が属するセッションの数。次に書く前回の範囲は、今回読み直した全記録から求める（`until` は全記録の最大の時刻、`sessions` は全記録のセッション数、`skipped` は今回飛ばしたファイル、`places` は今回指したディレクトリ）。前回の範囲が今の埋め込み・条件・判定の AIモデル・ディレクトリの集まりと違えば、記録を読む前に `CannotDraft` で断り、新しいファイルへ作り直すよう伝える。判定の指示文の変わりは見分けない（`IDEA-037-005`） |
