# INC-057 話しかけられていない間に、記憶を読み直して整理する夢

| 項目 | 内容 |
|---|---|
| Issue | #57 話しかけられていない間に、記憶を読み直して気づきを残す夢を起こせるようにする |
| PR | [#61](https://github.com/yadori-dev/yadori/pull/61) |
| 選んだ受入基準 | `AC-007` 整理が行われ、何を読み直し何に気づいたかが一回分の記録として残り、原文は減らない |

## 体験の変化

持ち主が `dream` を起こすと、宿りは前回の夢より後の記憶を読み直し、**残すものを選び、要点の層を作り、選んだ記憶をなぞって思い出しやすくする**。何を読み、何件を選び、どんな要点を残したかが夢の記録として残り、原文は一件も減らない。翌日話しかけると、前置きに前回の夢で残した要点が添い、応対がそれを踏まえる。`state` で最近の夢も読める。

人の眠りで記憶に起きることとして複数の学説が一致する点（[理論資料](../910_references/理論/README.md)）に寄せた。なぞられる（再生）、残るものは選ばれる、要点の形へ変わる、つながり全体は弱まる。それぞれをこう写す。どれも定説として固まったものではなく、限界は理論資料に書いてある。

| 学説が一致する点 | この増分での写し方 | 推論の印 |
|---|---|---|
| 起きていたときの記憶がなぞられ、妨げると成績が落ちる | 選んだ往復に思い出した記録を積む（[ADR-015](../010_decisions/ADR-015-思い出しやすさを思い出された記録から求め並べ替えの点数に混ぜない.md) の未決を決める。[ADR-018](../010_decisions/ADR-018-夢で選んだ記憶に思い出した記録を積む.md)） | 何をなぞるかを「選んだもの」に限るのは推論 |
| 残るものは選ばれる。全部が等しく残るのではない | 思い出された往復、気持ちが大きく動いた往復、同じ話題が繰り返し出た往復を選ぶ | 基準の三つと閾値は推論。人の選び方は「後で要る」と知らされた記憶が残る等の報告があるが、機械で写せる形の定説は無い |
| 残ったものは細部を落とし要点の形へ変わる | 選んだ往復を話題ごとにまとめた要点を、原文とは別の層に残す | 要点を対話する道具に書かせるのは手段 |
| つながり全体は弱まる方向へ動く（これは仮説の段階で、査読誌に批判もある） | 選ばれなかった往復には何も積まず、沈む | 弱め直しを「積まないことによる相対的な沈み」として写すのは推論。沈み方（並び）は `AC-016` の増分 |
| （一研究の観測）夢の中身は断片の組み替えで、まとまりの再現は 1〜2% | 気づきは、離れた記憶と結びついたときだけ一行添える脇役 | 一致点ではなく Fosse ら 2003 の観測。気づきの働きは証拠が薄い。無くてよい |

学説が割れている「眠りで気持ちが鎮まるか」は写さない。夢は気持ちを動かさない。

薄く作る。起こすのは手で（定期は持ち主の道具）。要点の層を意味で探すのは次の増分で、この増分では前置きに添えるだけ。

## 入口の例

```console
$ uv run python -m yadori dream
夢: 2026-09-01 09:00 から 22:40 までの 14 件を読み、5 件を選びました
要点: 2 件を残しました
  - テストが通らない件は原因がタイポで、三時間かかった
  - 図書館で借りた本の返却日は来月の五日
気づき: 無し
選んだ 5 件は思い出しやすくなりました

$ uv run python -m yadori dream
夢: 2026-09-01 22:40 から 23:10 までの 3 件を読みましたが、残すものはありませんでした

$ uv run python -m yadori dream
夢: 新しい記憶がありません。読み直しませんでした
```

## 手段の候補

- `IDEA-057-001`: 最近の記憶を全部渡して気づきを一文書かせる（最初の作り）。学説の一致点のうち「選ぶ」「要点化」「なぞる」を何も写さず、証拠の薄い「気づき」だけを主役にしている。採らない
- `IDEA-057-002`: 選ぶ基準を対話する道具に判定させる。呼び出しが増え、判定が呼ぶたびに揺れる（[ADR-011](../010_decisions/ADR-011-口を開くかの判定にAIモデルを使わない.md) と同じ理由）。採らない
- `IDEA-057-003`: 選ぶ基準は手元の値（思い出した記録、動きの大きさ、同じ話題の繰り返し）で決め、要点を書くところだけ対話する道具に渡す。選んだ往復に思い出した記録を積む。**採る。** 呼び出しは一晩に一度

## 要件とシステムテスト

| 要件と根拠 | 必要な振る舞い |
|---|---|
| `SPEC-057-001`（`AC-007`）前回より後の記憶から残すものを選ぶ | `dream` を起こすと、前回の夢の終わりより後の出来事の記憶（初回は全部）を古い順に、一度に 100 件まで読む（上限に達したらそこまでを読んだ範囲として記録し、残りは次の夢で読む。多すぎる記憶を一度に渡して道具が失敗し、記録が残らず同じ範囲を読み続けるのを避ける）。そのうち、思い出した記録が一件以上ある往復、気持ちの動きの大きさが 0.3 以上の往復、同じ範囲の別の往復と近さが既定の下限以上の往復（同じ話題の繰り返し）を選ぶ。新しい記憶が無ければ読み直さず、選ぶものが無ければ道具を呼ばず、どちらもその旨を出す。選ぶものが無くても、読んだ範囲は夢の記録に残す |
| `SPEC-057-002`（`AC-007`）選んだ往復を要点の層にし、なぞる | 選んだ往復の発話と返事だけを、名乗りを前置きに対話する道具へ渡し、話題ごとの要点（一行ずつ、一件以上）と、離れた記憶と結びついたときだけの気づき（無ければ無し）を受け取る。要点は原文とは別の層に、文、作った時刻、元になった往復、どの夢で作ったかと共に積む。選んだ往復には夢の時刻で思い出した記録を積み、選ばれなかった往復には積まない。夢の記録（起こした時刻、読んだ範囲、読んだ件数、選んだ件数、気づき）を積む。道具が失敗すれば要点も記録も思い出した記録も積まず、理由を返す。夢の前後で原文の件数は変わらない |
| `SPEC-057-003`（`AC-007`）前回の要点が応対に渡り、読める | 応対の前置きに、最新の夢で残した要点が並ぶ（無ければ添わない。気づきがあれば一行）。`state` に最近の夢（時刻、読んだ件数、選んだ件数、要点の数、気づき）が出る。`--at` で時点を指したときは、その時点より後の夢は無かったものとして扱う（それより前の別の夢は遡らない） |

| `ST-057-002` | `SPEC-057-002` | 要点の層と記録と原文と、なぞり | 決まった要点二つと気づき無しを返す差し替えの道具で `dream` を起こす。次に失敗する道具で起こす | 要点が二件、元の往復と夢の番号付きで残る。選んだ往復だけに思い出した記録が一件ずつ増える。夢の記録に読んだ件数と選んだ件数が残る。失敗では要点も記録も思い出した記録も増えない。どの後も原文は同じ件数 |

## 設計と結合テスト

### 設計判断

| 設計判断 | 実現する要件 | 構造と責務 |
|---|---|---|
| `AD-057-001` 選ぶ規則は domain が持ち、材料は保存先から読む | `SPEC-057-001` | domain の dream に、選ぶ規則（`Choosing`ではなく `Keeping`。選ばれた往復の並びを返す）を置く。材料は、往復ごとの思い出した記録、動き、同じ範囲の他の往復との近さ。近さは会話と同じ埋め込みと下限（`HowToRecall.relevance_floor`）で、その発話で話しかけられたら別の往復を思い出すか（問い合わせ側と覚える側）で見る。覚える側どうしで比べると意味を見る埋め込みでは日常の文がどれも近く出て、選ぶ働きを失う。範囲の外の古い記憶が上位を埋めて範囲の中の相手が切れないよう、下限以上を全部受け取ってから範囲の中だけを見る（費用は記憶の数に比例する。増えて困れば範囲を渡す口を足す）。閾値（動き 0.3、思い出した記録 1 件以上）は domain の定数に置き、推論であることを説明に書く。保存先の口に、時刻より後の出来事（`episodes_after`。前の版で足した）と、往復ごとの動き（`shifts` から `episode_id` で引く）を使い、新しい問い合わせは足さない |
| `AD-057-002` 要点は原文と別の表に、元の往復と夢へ結んで積む | `SPEC-057-002` | domain の memory に要点（`Gist`。文、作った時刻、元の往復の番号の並び、夢の番号）を置き、保存先に `gist` 表（`id`、`dweller_id`、`dream_id`、`made_at`、`text`）と `gist_source`（`gist_id`、`episode_id`）を足す。口は `record_gist`、`gists_of_dream(dream_id)`。原文の表には触れず、要点は消しても原文から作り直せる派生物として扱う（[ADR-006](../010_decisions/ADR-006-会話の原文を正典とし埋め込みを作り直せるインデックスとする.md) の考え方。ただし道具が書くので同じ文には戻らない）。夢の記録（`Dream`）に選んだ件数（`kept`）を足し、番号（`id`）を持たせる |
| `AD-057-003` 要点と気づきを書く相手は一つの口で、返りは決まった形 | `SPEC-057-002` | 気づきを書く口（`Noticing`）を、要点の並びと気づきを返す `Summarizing`（`summarize(identity, episodes) -> Summarized(gists, noticing)`）に変える。対話する道具の実装は、名乗りを前置きに、選んだ往復の発話と返事を渡し、「話題ごとに要点を一行ずつ、最後に気づきを一行（無ければ『気づき: 無し』）」の形で書かせ、切り出す。要点が一つも取れなければ `CannotDream`。夢の手順（`Dreaming`）は、選ぶ → 書かせる → 要点と記録と思い出した記録を積む、の順で、書かせる前には何も積まない |
| `AD-057-004` なぞりは思い出した記録を積むことで表し、並べ替えには混ぜない | `SPEC-057-002` | 選んだ往復に、夢の時刻で `record_retrieval` を積む。思い出しやすさを並べ替えの点数に混ぜない（[ADR-015](../010_decisions/ADR-015-思い出しやすさを思い出された記録から求め並べ替えの点数に混ぜない.md)）ので、この増分で思い出す結果は変わらない。沈む側の並びは `AC-016` の増分が決める。判断は [ADR-018](../010_decisions/ADR-018-夢で選んだ記憶に思い出した記録を積む.md) に残す |
| `AD-057-005` 前置きと `state` は最新の夢の要点を読むだけ | `SPEC-057-003` | 思い出したこと（`Recollection`）に最新の夢の要点の並び（`Dreamed`。夢の記録と要点）を添え、声の前置きが要点を箇条書きで、気づきがあれば一行足す。`state` は最近の夢を一行出す。`dream` の入口は選んだ件数と要点を画面に書く |
