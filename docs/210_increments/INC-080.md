# 短い返答の対象を夢で補う

対応: [Issue #80](https://github.com/yadori-dev/yadori/issues/80)。結果: [PR #87](https://github.com/yadori-dev/yadori/pull/87)。受入基準: `AC-001`、`AC-006`、`AC-007`、`AC-009`、`AC-010`、`AC-011`。

## 要件とシステムテスト

| 要件 | 外から見える振る舞い | システムテスト |
|---|---|---|
| `SPEC-080-001` 原文と会話の所属 | 会話の所属と直接の先行往復の出典を入口から渡し、原文とともに保存する。未保存・中断・再開で直接の先行往復を確認できなければ保留し、古い提案に結ばない。別の会話や別の宿りを根拠にしない | `ST-080-001` |
| `SPEC-080-002` 根拠付き補完 | 夢で、前後の空白だけを除きUnicodeコードポイントで20文字以下の返答を調べる。承認・否定・継続・選択の対象が先行文脈から特定できる場合だけ説明を足す。原文を変えず、条件付き承認を無条件承認・完了・恒久的好み・将来の操作権限に広げない | `ST-080-002` |
| `SPEC-080-003` 保留と再試行 | 通常の夢の読み終わりと別に、一回100件を処理する。補完済み・対象外・保留を区別し、失敗は未処理に残す | `ST-080-003` |
| `SPEC-080-004` 検索と根拠 | 原文と説明を検索に使い、同じ往復は一件にする。原文側の条件を維持し、説明側の下限は0.90とする。説明と対象原文と根拠を応対へ渡す。重要度・思い出した回数を補完だけで増やさない | `ST-080-004` |
| `SPEC-080-005` 再構築 | 保存済みの説明から索引を再構築し、文章生成はやり直さない | `ST-080-005` |
| `SPEC-080-006` 端末の結果 | yadori dream は補完・対象外・保留・失敗件数と残件の有無を示す。途中成功後の失敗も件数を出して終了状態1、失敗なしは0。補完例と根拠を表示する | `ST-080-006` |
| `SPEC-080-007` 道具の選択 | 共通設定の道具順とモデルを使う。未導入・用途非対応だけ次候補へ進み、実行後失敗は他モデルへ再送せず未処理を保持する | `ST-080-008` |

## 候補と設計

| 候補 | 判断 |
|---|---|
| `IDEA-080-001` 原文を詳しい文へ置換 | 原文を失うため採らない |
| `IDEA-080-002` 夢の要約だけ変更 | 古い要点の検索と選別前に落ちる返答を救えないため採らない |
| `IDEA-080-003` 原文に結ぶ説明と専用索引 | 原文保存と独立した再試行を両立するため選ぶ |

| 設計 | 責務と境界 | 結合テスト |
|---|---|---|
| `AD-080-001` 会話の所属 | 会話の入口が名前空間付き所属を渡す。保存先が出典で繋がる同じ所属の先行往復だけを読む。端末とDiscordは稼働中の連続成功往復、Claude/Codexは同じ起動内で通知順を確認した往復、agyは履歴で直接の先行発話を確認した往復を繋ぐ。欠損を時刻で推測しない。所属のない既存原文は推定しない | `IT-080-001` |
| `AD-080-002` 補完の記録 | 対象・規則の版で一意にし、説明・種別・保留理由・生成時刻・根拠を原文と別に保存。検索用の数値表現が完成してから説明と同じ取引で確定する | `IT-080-002` |
| `AD-080-003` 生成の境界 | 先行往復を最大3件、長さ上限を超える文脈は切り詰めず保留にする。対象の返事や未来の結果は渡さない。道具の出力は形・種別・根拠の所属を検証する。道具の失敗を保留へ変換しない | `IT-080-003` |
| `AD-080-004` 検索の分離 | 原文索引と補完索引の結果を対象ごとにまとめる。通常の夢の重要度選別は原文索引を使い続ける。索引再構築は原文と保存済み説明を読む。説明側の下限を原文側と分けて適用する | `IT-080-004` |
| `AD-080-005` 進捗と失敗の境界 | `SPEC-080-003` / `SPEC-080-006` / `SPEC-080-007` を実現する。端末入口が補完を通常夢より先に呼び、件数と例を即表示する。最初の生成・数値化・保存失敗でバッチを止め、成功分を保持して終了1。通常夢へ進まない。補完後に通常夢が失敗しても表示済み件数を維持して終了1。共通の道具選択を生成側へ渡す | `IT-080-005` |

## 品質の判定

架空の評価セットを処理前に固定する。同一の既定埋め込み、原文の近さ下限0.85・説明の下限0.90、上位5件、直近0件で前後を比較する。期待する往復と出てはいけない別件の往復を問ごとに固定する。最新の夢を入れ替えた後にも検索する。補完採用率、保留、誤補完、時間を報告する。合格は期待する往復が上位に入る問が増え、禁止混入問と既存評価の退行が増えないこと。`SPEC-080-004` に対応する `ST-080-007` は調整に使ったセットとは別に事前固定した架空セットの前後比較を実行し、この条件を確認する。条件付き承認「下書きはお願い。公開は別途確認」、否定、継続、選択を含める。架空例の成功を実会話全般の精度保証としない。実会話の評価は端末だけに保存する。

新しいGUI、公開API、定期実行は作らない。補完用の独立設定は今回作らず、共通の道具順・モデル設定を使う。
