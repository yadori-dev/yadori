## 選んだ受入基準

| 基準 | 判定する状態 |
|---|---|
| `AC-001` | 前のセッションで話した内容について、説明も検索の指示もしないまま、それを踏まえた応対が返る |
| `AC-002` | 一度の応対について、思い出した記憶の一覧、近さの値、渡した順序を後から読める |
| `AC-006` | 評価セットの各件で、期待した記憶が定めた順位までに入り、出てはいけない記憶が閾値を越えない |
| `AC-013` | 書いた名乗りのとおりの名前と話し方で応対が返り、会話を重ねてもその部分は変わらない |

対応する場面は `SC-001`（昨日の続きを話す）、`SC-009`（見当違いの返事の理由を調べる）、`SC-014`（宿りに名乗りを与える）である。

**名乗りを外せない理由。** Discord では返事を作るのが宿り自身であり、名乗りが無ければ誰でもない相手の応対になる。気持ちと性格は無くても会話は成立するが、名乗りが無いと会話そのものが始まらない。

## この増分で満たす構造上の制約

受入基準ではないが、後から入れると移行が必要になるため、この増分で形を確定する。

- 記憶、状態のすべてが持ち主を持つ（[ADR-008](../010_decisions/ADR-008-記憶の持ち主を最初から記録する.md)）
- 会話の原文を消さず、索引を捨てて作り直せる（[ADR-006](../010_decisions/ADR-006-会話の原文を正典とし埋め込みを作り直せる索引とする.md)）
- 会話の入口を「思い出す」と「覚える」の二つにする（[ADR-012](../010_decisions/ADR-012-会話の入口を思い出すと覚えるの二つに分ける.md)）
- 名乗りを上書きせず版で持ち、応対がどの版で作られたかを記録する（[ADR-013](../010_decisions/ADR-013-名乗りは積まず書いたものを版で持つ.md)）
- 層の依存を内向きにする（[ADR-004](../010_decisions/ADR-004-層の依存を内向きにし内側を機能で割る.md)）

## 今回扱わないこと

- 気持ち、性格（`REQ-004` `REQ-005`）
- 名乗りの以前の版を読む入口（`AC-014`）。保存の形だけ確定し、読む手段は作らない
- 夢と気がかり、宿りから話しかけること（`REQ-007` `REQ-008`）
- Claude Code、Codex、Gemini への出ていく先（`REQ-003`）
- 過去の対話の履歴を最初の記憶として取り込むこと

**なぜ Discord から始めるか。** 思い出す質は、実際に会話しないと良し悪しが分からない。Discord では宿り自身が返事を作るため、思い出した内容がそのまま応対に現れ、その場で判定できる。対話する道具へのフックを先に作っても、返事を作るのは道具側であり、思い出す質の良し悪しが応対から切り分けられない。

**なぜ気持ちと夢を後にするか。** どちらも思い出した記憶を材料にする。思い出す部分が濁ったままだと、気持ちの動きも夢の気づきも濁った材料から作られ、何が原因か切り分けられない。

## 仮定していること

未決事項のうち、次を仮定してこの増分を進める。

- 宿り自身を表す言葉は決めない。この増分の範囲では、記憶と名乗りと持ち主だけで足りる
- 名乗りと性格の境目は、この増分では持ち主が書いた文章がすべてであり、性格が無いため衝突しない
- 思い出した記憶が気持ちを動かすかは決めない。この増分に気持ちが無いため影響しない
- 評価セットの件数と作り方は、この増分の中で最初の形を作り、以降で育てる
