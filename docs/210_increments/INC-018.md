## 体験の変化

保守する開発者は、発話と、そのとき出るべき記憶・出てはいけない記憶の組を評価セットとして用意し、現在の条件で測る。件ごとに、期待した記憶が何番目に出たか、出てはいけない記憶がどれだけ近いと判定されたかを読む。

条件を一つ変えてもう一度測ると、件ごとの差が、良くなった点と悪くなった点に分かれて出る。採るか戻すかを、感覚ではなく測った値を根拠に決める。

そのうえで、`INC-006` で根拠なく置いた三つの値（直近を渡す往復数、意味の近さの下限、一度に渡す件数）を測った結果から決め直す。

測るのは意味で探す側だけである。直近のやりとりは意味を見ずに常に渡すため、測ると新しさが混ざり、条件を変えた効果を読めなくなる（[ADR-015](../010_decisions/ADR-015-思い出しやすさを思い出された記録から求め並べ替えの点数に混ぜない.md)）。

一度の会話について何を思い出したかを読む体験は `AC-002` が持ち、別の増分で扱う。よく話すことほど詳しく思い出すことは `AC-016` が持つ。

## 入口の例

```console
$ uv run python -m yadori.eval
15件中 12件で期待した記憶が上位3件に入った
出てはいけない記憶が下限を越えた: 2件

$ uv run python -m yadori.eval --floor 0.20
15件中 14件（+2）／出てはいけない記憶が越えた: 5件（+3）
良くなった: 「ベランダの野菜どう」でトマトの件が 4位 → 1位
悪くなった: 「明日の天気」で無関係な3件が下限を越えた
```

数値と語は増分の中で決める。読み取れることは、件ごとの順位、出てはいけない記憶の近さ、変更前後の差である。

## 手段の候補

- `IDEA-018-001`: 評価セットをコードの中に書く。近いが、条件を変えて何度も回すたびにコードを触ることになり、測った履歴と混ざるため採らない
- `IDEA-018-002`: 評価セットを架空の会話を書いたファイルとして持つ。差分で読め、件を足すのが軽い。採る
- `IDEA-018-003`: 広く使われる指標（平均の順位など）を一つの数にまとめて出す。全体の良し悪しは分かるが、どの件が良くなりどの件が悪くなったかを読めないため、これだけでは採らない
- `IDEA-018-004`: 件ごとの順位と近さをそのまま並べ、変更前後の差を件ごとに出す。読む量は増えるが、悪くなった件を名指しできる。採る
- `IDEA-018-005`: 埋め込みを、文字の重なりではなく意味を見る実装へ替える。言い換えだけが近い発話に効くはずだが、効くかどうかもこの仕組みで測ってから決める。採否は測った後

## 要件とシステムテスト

| 要件と根拠 | 必要な振る舞い |
|---|---|
| `SPEC-018-001`（`AC-006`）評価セットから件ごとの結果を出す | 発話、出るべき記憶、出てはいけない記憶の組を受け取り、件ごとに、期待した記憶が何番目に出たか（出なければ出なかったことが分かる形で）と、出てはいけない記憶の近さを返す。測るのは意味で探す側だけで、直近のやりとりは数えない。全体の要約は件ごとの結果から導き、要約だけを返さない |
| `SPEC-018-002`（`AC-011`）変更の前後を件ごとに比べる | 条件を変えて二度測った結果を受け取り、件ごとの差を、良くなった点と悪くなった点に分けて返す。変わらなかった件は差として出さない。全体では良くなっても悪くなった件があれば、その件を名指しできる |
| `SPEC-018-003`（`AC-006`）測れないものを測ったことにしない | 評価セットが指す記憶が保存に無い、または索引を持たない記憶がある場合、測らずに理由を返す。欠けたまま測ると、順位が上がった理由が条件の変更なのか記憶の欠落なのか分からなくなる |

### 個々のシステムテスト

評価セットは架空の会話で作る。利用者の実際の会話を使わない。

| テスト | 対応 | 観点 | 入力 | 期待する結果 |
|---|---|---|---|---|
| `ST-018-001` | `SPEC-018-001` | 件ごとの順位と近さが読める | 架空の記憶を十件入れ、期待する記憶を指した評価セット三件で測る | 件ごとに、期待した記憶の順位と、出てはいけない記憶の近さが出る。上位に出なかった件は、出なかったことが分かる。全体の要約が件ごとの結果と一致する |
| `ST-018-002` | `SPEC-018-001` | 直近は測らない | 期待する記憶が直近の窓に入る評価セットで測る | その記憶は意味で探す側に現れず、期待どおりに出なかったこととして出る。直近に入っていたことを理由に良い結果としない |
| `ST-018-003` | `SPEC-018-002` | 良くなった件と悪くなった件を名指しできる | 下限を下げて二度測る。一件は順位が上がり、別の一件は出てはいけない記憶が越えるようにする | 良くなった件と悪くなった件が別々に出る。変わらなかった件は出ない。全体では良くなっていても、悪くなった件が消えない |
| `ST-018-004` | `SPEC-018-003` | 欠けたまま測らない | 評価セットが存在しない記憶を指す場合と、索引を消した記憶がある場合の二通りで測る | どちらも測らずに理由が返る。数値は出ない |
