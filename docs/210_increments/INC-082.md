# 根拠が足りないときに宿り自身が記憶を探す

対応: [Issue #82](https://github.com/yadori-dev/yadori/issues/82)。結果: [PR #89](https://github.com/yadori-dev/yadori/pull/89)。受入基準: `AC-001`、`AC-002`、`AC-003`、`AC-006`、`AC-010`、`AC-011`。

## 設計

| 設計 | 責務と境界 | テスト |
|---|---|---|
| `AD-082-001` 一時台帳と固定人物 | 起動専用領域のSQLiteに固定人物、往復キー、回数、応答量、参照、返した頁を持つ。既存の設定スナップショットを自動検索・保存・MCPへ引き継ぐ。フックが開始・終了・中断を通知する。各呼出しはフックが渡した不透明な往復キーを必須にし、遅れた呼出しを新しい往復へ混ぜない。処理前に回数予約を確定し、失敗やプロセス終了でも戻さない。応答量と返した頁は返却前に別の取引で確定し、台帳を確認できなければ実行しない | `IT-082-001` |
| `AD-082-002` 検索と原文の手順 | 自動検索の組立てを再送せず、原文索引・補完索引だけを使い、候補を広めに読む下限0.75で上位を探す。候補であることは決定の根拠が揃ったことを意味しない。自動検索の下限は変えない。自動提示候補には印を付け、フックで省略された原文を読めなくしない。原文取得は対象、直接の先行1往復、直接の後続1往復、補完の根拠最大3往復を重複除去して読む。後続が分岐して一意でなければ省略を明示する。最初の取得で本文一式を台帳へ固定し、以後は同じ本文を頁送りする。後続往復や補完が増えても同じ参照の位置を変えない。時刻順では繋がない | `IT-082-002` |
| `AD-082-003` MCPの境界 | 公式Python SDKでstdio接続を持ち、`recall_search(turn, query, limit=3)` と `recall_get(turn, reference, offset=0)` だけを公開する。呼出し元の引数から人物や保存先を選ばせない。MCP説明とフックの短い指示は十分なら検索不要、原文確認前に断定しない、上限後は確認へ戻ると伝える | `IT-082-003` |
| `AD-082-004` 起動への接続 | Codex/Claude/agyの一時設定へ予約名 `yadori_memory` の接続を追加する。共通の読み取り道具だけを許可し、既存の明示的拒否には従う。MCP接続用の `yadori _memory-mcp <専用領域>` を用意し、接続失敗を理由付きで見せる | `IT-082-004` |

## 停止の範囲と対象外

上限は追加検索処理と受け付けた応答本文に対するもの。上限後の短い拒否、通信の付加情報、モデル自身の再呼出し回数・総トークン・対話全体の終了をサーバーだけで保証しない。作業中のホストを強制終了しない。実入口で上限後に応対へ戻らない場合は未達とする。

Codex/Claude/agyを対象とする。agyはLinuxの1.2.1/1.2.2を許可し、今回の実入口は1.2.2で確認する。Discord・専用チャット、記憶の管理GUI、編集・削除、外部メールや文書の検索は作らない。

MCPの採用自体をトークン削減の根拠にしない。測定で増加した場合もそのまま報告する。
