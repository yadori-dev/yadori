# INC-079 人物の対話設定と共通の道具選択

対応する要求は [Issue #79](https://github.com/yadori-dev/yadori/issues/79)。受入基準は `AC-003`（道具を変えても同じ相手として続く）、`AC-012`（保存先と会話を渡す相手が分かる）。

## 要件とシステムテスト

| 識別子 | 内容 |
|---|---|
| `SPEC-079-001` | setting と未設定の対話起動は同じ検証・確認付き設定を使う。名前、呼び名、持ち主、複数行の名乗り、道具順を編集でき、取消・入力終了・失敗は起動も部分保存もしない。非対話起動は質問せず設定方法を案内する |
| `ST-079-001` | `SPEC-079-001` 初回、部分設定、不正値、既存設定、取消、EOF、保存失敗を端末入力から比較し、保存後の再読込と元の起動の一回継続を確認する |
| `SPEC-079-002` | 名前の編集と人物切替を分け、同じ人物の識別子・記憶・状態を保持する。設定は次の起動から反映する |
| `ST-079-002` | `SPEC-079-002` 名前・名乗り編集と人物 A→B→A を行い、原文、名乗りの版、気持ちを比較する。候補無し・取消と実行中の設定固定を確認する |
| `SPEC-079-003` | 引数なし、chat、discord、dream、evals draft は共通の道具順を使う。既定は codex、claude、agy。未導入・用途非対応だけを理由付きで飛ばし、選択後の失敗は再送しない。明示指定は共通順を変えない |
| `ST-079-003` | `SPEC-079-003` 設定無し、順変更、未導入、用途非対応、不正順、候補無し、明示指定を比較する。夢の記憶無しと判定不要では道具を要求しない |
| `SPEC-079-004` | 内部呼び出しは対話画面を開かず必要な入力だけを渡し、通常の履歴と作業場所から分離する。Discord へ失敗の詳細を送らない |
| `ST-079-004` | `SPEC-079-004` 実物で応対・要約・判定の返り値を確認し、専用環境の削除と通常会話への未保存を確認する。操作前後を録画する |

## 設計と結合テスト

| 識別子 | 内容 |
|---|---|
| `AD-079-001` | YADORI_HOME/settings.toml 一ファイルに version、active、priority と people の人物設定を保存する。旧 dweller.toml と identity.md は初回保存時に取り込み原本を残す。既存 nickname 由来の id を固定する。記憶 DB は移動せず既存の人物 id で分離する。候補は people に用意した人物とする。未知の設定値も保持する |
| `IT-079-001` | `AD-079-001` 再読込・旧設定移行・二人物の記憶・同時編集検出・差替え失敗で原本を比較する |
| `AD-079-002` | 共通選択は処理開始時の設定を保持し、最初の必要な呼出時に道具を一度選ぶ。内部の道具接続だけを差し替え、応対・夢・判定の文章と返り値の意味を維持する。旧 model は Claude 専用として移行し他の道具には渡さない |
| `IT-079-002` | `AD-079-002` 同じ順を各用途へ渡し、実行途中の設定変更・失敗でも送信先が変わらないことを確認する。モデルの分離と無呼出の経路を検査する |
| `AD-079-003` | 対話起動は既存の専用起動を使う。起動単位の設定の写しをフックへ渡し、別プロセスの設定変更で人物や名乗りを変えない。内部実行は一時作業場所・専用設定・ツール無しで一回の結果を受け取る |
| `IT-079-003` | `AD-079-003` 実 Codex/Claude/agy の非対話契約、設定・履歴分離、実行失敗後の未再送を確認する |

保存と移行の判断は ADR-023。専用端末チャットの移行先は `yadori chat`。順からの候補除外は許可するが空・重複・未知名は拒否する。人物追加・削除の画面は対象外で、別人物は people 表を手で追加する。公開は互換性変更を含む次のマイナー版とする。

非対話の一次仕様: [Codex exec](https://learn.chatgpt.com/docs/non-interactive-mode)、[agy の headless mode](https://antigravity.google/docs/cli/headless/)。利用中の実物のヘルプと、通常検査から分けた契約テストでも照合する。
