# INC-025 別の言い方で尋ねても思い出す

| 項目 | 内容 |
|---|---|
| Issue | #25 別の言い方で尋ねても思い出せるようにする |
| PR | [#28](https://github.com/yadori-dev/yadori/pull/28) |
| 選んだ受入基準 | `AC-017` 語が重ならなくても思い出す |

## 体験の変化

話す人は、前に使った語を思い出さなくてよい。「ベランダにトマトの苗を植えました」と話した後、「植物の世話について教えてください」と尋ねても、宿りはその件を踏まえて答える。覚えているのは話題であって語ではない、という前提で話せる。

持ち主の定額契約で動かす前提は変わらない。AIモデルの提供元への鍵を必要とせず、手元で完結する。

替えた効果は `INC-018` の仕組みで測る。架空の評価セットと、実際の会話から作った評価セットの両方で確かめる。架空の会話だけでは、語を選んだ本人が都合よく当ててしまう（[ADR-010](../010_decisions/ADR-010-思い出す質を評価セットで判定する.md)）。

よく話すことほど詳しく思い出すこと（`AC-016`）、一度の会話の思い出しを読む入口（`AC-002`）は別の増分が持つ。実際の会話から評価セットを作る道具は作らない。手で書ける範囲で足りることを `INC-018` の確認で確かめた。

## 入口の例

```console
> ベランダにトマトの苗を植えました
そら: いいですね。日当たりに気をつけてください。
（別の話題をいくつか挟む）
> 植物の世話について教えてください
そら: トマトの苗を植えられたと伺いました。水やりは……

$ uv run python -m yadori measure
埋め込み: paraphrase-multilingual-MiniLM-L12-v2/fastembed-0.8.0
条件: 直近6往復・上限5件・下限0.5
5問中 4問で期待したやりとりが上位3件に入った
出てはいけないやりとりが出た問: 0問
  満たさず: 「手続きの話を引く」期待: tax 出ず
```

## 手段の候補

- `IDEA-025-001`: 思い出す条件をさらに調整する。`INC-018` で測ったとおり、語が重ならない問は下限をどう動かしても引けず、緩めると先に無関係な記憶が混ざる。届かないため採らない
- `IDEA-025-002`: AIモデルの提供元の埋め込みへ鍵で繋ぐ。質は見込めるが、定額契約で動かす前提（[ADR-016](../010_decisions/ADR-016-応対は対話する道具を通して作り、その道具の文脈を持ち込まない.md)）を崩し、会話のたびに課金が積み上がるため採らない
- `IDEA-025-003`: 手元で動く意味の埋め込みへ、置き換える。鍵が要らず、外へも繋がらない。**三つの埋め込みを測り、`paraphrase-multilingual-MiniLM-L12-v2` を採る。** 実際の会話から作った評価セットで、語の重なりを見る実装より多くの問を満たし、無関係な記憶も混ざらない。三つのうちもっとも小さい
- `IDEA-025-004`: 手元で動く埋め込みが複数あるため、`INC-018` の仕組みで同じ評価セットに当てて比べ、測った値で選ぶ。採る。選ぶために使った実装と入口は残す
- `IDEA-025-005`: 置き換えるのではなく、語の重なりで探す道と意味で探す道を別々に持ち、両方から渡す。**実装して測ったが、意味で探す道だけの場合と満たした問が変わらなかったため採らない。** インデックスと検索が二倍になり、渡す量も増えるのに、得るものが無い。仕組みは残す。埋め込みどうしを比べるのに要る

## 要件とシステムテスト

| 要件と根拠 | 必要な振る舞い |
|---|---|
| `SPEC-025-001`（`AC-017`）語が重ならなくても思い出す | 話しかけられた文章と語が重ならないやりとりでも、話題が同じなら探した記憶に現れる。無関係なやりとりが混ざる問は、替える前より増えない。架空の評価セットと、実際の会話から作った評価セットの両方で成り立つ |
| `SPEC-025-002`（`AC-017`）替えても原文は失われず、作り直せる | 埋め込みを替えると、それまでのインデックスは使えなくなる。原文は一件も失われず、インデックスを作り直せば、替える前から保存されている記憶も新しい埋め込みで探せる。どの埋め込みで作ったインデックスかを、インデックスごとに読める |
| `SPEC-025-003`（`AC-017`）鍵を要求せず手元で完結する | AIモデルの提供元への鍵が無く、外へ繋がらない状態でも思い出せる。導入したものが手元に無い場合は、思い出す前に理由を返す。何を導入すればよいかが理由から分かる |

## 設計と結合テスト

### 設計判断

| 設計判断 | 実現する要件 | 構造と責務 |
|---|---|---|
| `AD-025-001` 違う埋め込みで作ったインデックスは使わない | `SPEC-025-002` | インデックスは作った埋め込みの名前を持つ（`INC-006` から記録している）。探すときは、いまの埋め込みで作ったインデックスだけを見る。違う埋め込みのインデックスは無視し、その記憶は探した側に現れない。原文は残るため、作り直せば現れる。無視する側と作り直す側を同じ規則で決めるため、「インデックスを持たない記憶」の判定にもいまの埋め込みを使う。長さの違う数の並びを比べようとして落ちることも、違う埋め込みの値を混ぜて誤った近さを出すことも、これで起きない |
| `AD-025-002` 手元に無ければ何も書く前に断る | `SPEC-025-003` | 手元で動く埋め込みは、導入されていなければ使えない。**覚えるときは、原文を書く前に数の並びを作る。** 使えなければそこで断り、原文もインデックスも書かない。作った並びを原文の確定後にインデックスとして書くため、`AD-006-003` の「インデックスの作成に失敗しても原文は残る」も変わらない。理由には何を導入すればよいかを含める。会話の口はこれを外へ伝えるだけで、導入の面倒は見ない |
| `AD-025-004` 以前の形のインデックスの表は捨てて作り直す | `SPEC-025-002` | インデックスを埋め込みごとに持つ形へ変えると、以前の版が作った保存先の表は形が違う。インデックスは原文から作り直せる派生物（[ADR-006](../010_decisions/ADR-006-会話の原文を正典とし埋め込みを作り直せるインデックスとする.md)）なので、開くときに形を確かめ、違えばインデックスの表だけ捨てる。原文の表には触れない。捨てたインデックスは起動時の作り直しで戻る。同じ埋め込みでも動かす道具の版で数の並びが変わるため、インデックスの名前には道具の版も含める |
| `AD-025-003` 測るときに埋め込みを選べ、道を複数持てる | `SPEC-025-001` | どの埋め込みを採るかは、同じ評価セットに当てて測って選ぶ。測る手順は埋め込みを外から受け取っており（`AD-018-001`）、入口から選べるようにする。思い出す手順は道を複数受け取れ、道ごとに探して交互に並べる。点数は混ぜず、探した記憶はどの道で出たかを持つ。既定を変えても、測る入口から以前のものを指して測り直せる |

### 個々の結合テスト

| テスト | 対応 | 観点 | 入力 | 期待する結果 |
|---|---|---|---|---|
| `IT-025-001` | `AD-025-001` | 違う埋め込みのインデックスを混ぜない | 一つ目の埋め込みで記憶を覚えさせた保存先を、二つ目の埋め込みに差し替えて思い出す。次にインデックスを作り直してもう一度思い出す | 作り直す前は探した記憶が空で、落ちない。原文の件数は変わらない。作り直した後は同じ記憶が探せる。インデックスを持たない記憶の一覧が、作り直す前は全件、作り直した後は空になる |
| `IT-025-002` | `AD-025-002` | 使えなければ何も書く前に断る | 埋め込みが使えない状態で、思い出すと覚えるの両方を呼ぶ | どちらも理由が返る。原文もインデックスも増えない |
| `IT-025-003` | `AD-025-003` | 二つの道から渡せ、どちらで出たかを読める | 二つの道で覚えさせ、思い出す | 探した記憶が両方の道から出て、どちらで出たかを持つ。同じ記憶が二つの道で出ても、渡すのは一度だけである |
