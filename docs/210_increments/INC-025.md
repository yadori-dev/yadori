# INC-025 別の言い方で尋ねても思い出す

| 項目 | 内容 |

## 体験の変化

話す人は、前に使った語を思い出さなくてよい。「ベランダにトマトの苗を植えました」と話した後、「植物の世話について教えてください」と尋ねても、宿りはその件を踏まえて答える。覚えているのは話題であって語ではない、という前提で話せる。

持ち主の定額契約で動かす前提は変わらない。模型の提供元への鍵を必要とせず、手元で完結する。

替えた効果は `INC-018` の仕組みで測る。架空の評価セットと、実際の会話から作った評価セットの両方で確かめる。架空の会話だけでは、語を選んだ本人が都合よく当ててしまう（[ADR-010](../010_decisions/ADR-010-思い出す質を評価セットで判定する.md)）。

よく話すことほど詳しく思い出すこと（`AC-016`）、一度の会話の思い出しを読む入口（`AC-002`）は別の増分が持つ。実際の会話から評価セットを作る道具は作らない。手で書ける範囲で足りることを `INC-018` の確認で確かめた。

## 入口の例

```console
> ベランダにトマトの苗を植えました
そら: いいですね。日当たりに気をつけてください。
（別の話題をいくつか挟む）
> 植物の世話について教えてください
そら: トマトの苗を植えられたと伺いました。水やりは……

$ uv run python -m yadori measure
5件中 5件で期待したやりとりが上位3件に入った
出てはいけないやりとりが出た件: 0件
```

## 手段の候補

- `IDEA-025-001`: 思い出す条件をさらに調整する。`INC-018` で測ったとおり、語が重ならない件は下限をどう動かしても引けず、緩めると先に無関係な記憶が混ざる。届かないため採らない
- `IDEA-025-002`: 模型の提供元の埋め込みへ鍵で繋ぐ。質は見込めるが、定額契約で動かす前提（[ADR-016](../010_decisions/ADR-016-応対は対話する道具を通して作り、その道具の文脈を持ち込まない.md)）を崩し、会話のたびに課金が積み上がるため採らない
- `IDEA-025-003`: 手元で動く意味の埋め込みへ、置き換える。鍵が要らず、外へも繋がらない。**三つの候補を測り、`paraphrase-multilingual-MiniLM-L12-v2` を採る。** 実際の会話から作った評価セットで、語の重なりを見る実装より多くの件を満たし、無関係な記憶も混ざらない。候補のうちもっとも小さい
- `IDEA-025-004`: 手元で動く候補が複数あるため、`INC-018` の仕組みで同じ評価セットに当てて比べ、測った値で選ぶ。採る。選ぶために使った実装と入口は残す
- `IDEA-025-005`: 置き換えるのではなく、語の重なりで探す道と意味で探す道を別々に持ち、両方から渡す。**実装して測ったが、意味で探す道だけの場合と満たした件が変わらなかったため採らない。** 索引と検索が二倍になり、渡す量も増えるのに、得るものが無い。仕組みは残す。埋め込みの候補を比べるのに要る

## 要件とシステムテスト

| 要件と根拠 | 必要な振る舞い |
|---|---|
| `SPEC-025-001`（`AC-017`）語が重ならなくても思い出す | 話しかけられた文章と語が重ならないやりとりでも、話題が同じなら探した記憶に現れる。無関係なやりとりが混ざる件は、替える前より増えない。架空の評価セットと、実際の会話から作った評価セットの両方で成り立つ |
| `SPEC-025-002`（`AC-017`）替えても原文は失われず、作り直せる | 埋め込みを替えると、それまでの索引は使えなくなる。原文は一件も失われず、索引を作り直せば、替える前から保存されている記憶も新しい埋め込みで探せる。どの埋め込みで作った索引かを、索引ごとに読める |
| `SPEC-025-003`（`AC-017`）鍵を要求せず手元で完結する | 模型の提供元への鍵が無く、外へ繋がらない状態でも思い出せる。導入したものが手元に無い場合は、思い出す前に理由を返す。何を導入すればよいかが理由から分かる |

## 設計と結合テスト

### 設計判断

| 設計判断 | 実現する要件 | 構造と責務 |
|---|---|---|
| `AD-025-001` 違う模型で作った索引は使わない | `SPEC-025-002` | 索引は作った模型の名前を持つ（`INC-006` から記録している）。探すときは、いまの模型で作った索引だけを見る。違う模型の索引は無視し、その記憶は探した側に現れない。原文は残るため、作り直せば現れる。無視する側と作り直す側を同じ規則で決めるため、「索引を持たない記憶」の判定にもいまの模型を使う。長さの違う数の並びを比べようとして落ちることも、違う模型の値を混ぜて誤った近さを出すことも、これで起きない |
| `AD-025-002` 手元に無ければ何も書く前に断る | `SPEC-025-003` | 手元で動く埋め込みは、導入されていなければ使えない。**覚えるときは、原文を書く前に数の並びを作る。** 使えなければそこで断り、原文も索引も書かない。作った並びを原文の確定後に索引として書くため、`AD-006-003` の「索引の作成に失敗しても原文は残る」も変わらない。理由には何を導入すればよいかを含める。会話の口はこれを外へ伝えるだけで、導入の面倒は見ない |
| `AD-025-003` 測るときに埋め込みを選べ、道を複数持てる | `SPEC-025-001` | どの埋め込みを採るかは、同じ評価セットに当てて測って選ぶ。測る手順は埋め込みを外から受け取っており（`AD-018-001`）、入口から選べるようにする。思い出す手順は道を複数受け取れ、道ごとに探して交互に並べる。点数は混ぜず、探した記憶はどの道で出たかを持つ。既定を変えても、測る入口から以前のものを指して測り直せる |
