# INC-102 普段の対話環境に宿りを加える

要求は [Issue #102](https://github.com/yadori-dev/yadori/issues/102)。選んだ受入基準は `AC-001` と `AC-003`。普段の設定・確認・履歴を維持し、宿りの記憶と名乗りを加える。

## 要件とシステムテスト

| 識別子 | 内容 |
|---|---|
| `SPEC-102-001` | 通常の設定、接続先、スキル、フック、信頼確認を維持して起動する。信頼と認証は道具が判断する |
| `SPEC-102-002` | 道具の履歴を残し、再開の引数を渡せる。宿りの作業状態だけを終了時に片付ける |
| `SPEC-102-003` | 親子関係が直列の完成応対と、同じ往復内の追加発話を順序を保って取り込む。分岐や不明な対応は保留する。既存の原文や先行関係を上書きしない。通常履歴へ残った宿り自身の会話は二重に取り込まない |
| `SPEC-102-004` | 起動前の取り込みは短い結果だけを表示し、失敗は隠さない。手動取り込みでは詳細を読める |
| `ST-102-001` | `SPEC-102-001` 通常起動と宿り経由の起動を同じ使い捨て設定で比較し、未信頼の場所では道具自身の確認が出ること、通常のフックと宿りの記憶が両方動くことを確認する |
| `ST-102-002` | `SPEC-102-002` 終了後も通常の履歴が残り、再開の指定が道具へ届く。再開した会話の新しい一往復を宿りへ保存できる |
| `ST-102-003` | `SPEC-102-003` 直列、分岐、追加発話、中断、重複行、再実行を比較する。既存原文が別なら上書きせず止まる |
| `ST-102-004` | `SPEC-102-004` 注意の多いログを起動準備で読み、手動取り込みと保存結果を比較する。破損は両方で失敗する |

## 設計と結合テスト

| 識別子 | 内容 |
|---|---|
| `AD-102-001` | `SPEC-102-001` `SPEC-102-002` 道具の通常設定を直接使用し、宿りの接続とフックだけを起動時に追加する。一時ディレクトリは宿りの作業状態だけを持つ。agy は追加ディレクトリを使い、通常の履歴の根を固定した上で会話ごとに回復状態を分ける |
| `AD-102-002` | `SPEC-102-003` 会話の原文を読む境界で、同じ往復に属する文を順序どおりに結ぶ。Claudeは親子関係が続く場合だけ結ぶ。Codexは同じturn内の依頼を結ぶ。後続への先行関係は既存規則を維持する。Claude の promptId を宿りのフックの出典と照合し、ログ行の uuid と区別する。照合用の識別子は保存済み外部原文の同一性を変えない |
| `AD-102-003` | `SPEC-102-004` 起動準備だけ表示を短くし、手動取り込みは詳細を表示する。入力の検証と保存の処理は共用する |
| `IT-102-001` | `AD-102-001` 通常設定の場所と環境を保ち、追加する設定に既存設定の無効化や信頼の捏造がないことを確認する。再開の引数を子プロセスへ渡す |
| `IT-102-002` | `AD-102-002` ログ読取から保存・再実行までを通し、重複と原文変更がないことを確認する |
| `IT-102-003` | `AD-102-003` 同じ入力で保存結果が一致し、表示だけが変わることを確認する |

## 境界

普段の指示と宿りの名乗りが矛盾した場合の話し方、外部フックの独自動作まで同一とは保証しない。既存の会話ログと記憶を削除・更新して件数だけを減らさない。内部の要約・判定に使う隔離した呼び出しは変更しない。
