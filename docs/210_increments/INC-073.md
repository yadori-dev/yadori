# apt で導入・更新する

対応する要求は [Issue #73](https://github.com/yadori-dev/yadori/issues/73) の完了条件。新しい配布要求であり、会話・記憶の既存 AC は変更しない。

## 要件とシステムテスト

| 識別子 | 内容 |
|---|---|
| `SPEC-073-001` | Ubuntu 24.04 / Debian 13 の amd64 で署名済み配布元から apt で導入・更新でき、任意の作業場所から yadori state を使える |
| `SPEC-073-002` | 更新・削除で利用者の設定・記憶を変えない。不正な配布元の署名を拒否する |
| `SPEC-073-003` | GitFlow で main に取り込んだコードの GitHub Release を発行すると、pyproject.toml や uv.lock の番号を編集せず、Git タグから求めた版で .deb と apt 配布元を自動発行する。不一致と未統合のタグは公開しない |
| `ST-073-003` | `SPEC-073-003` packaging/apt/test-version.sh でpyproject を変更せず v1.2.3 → v1.2.4 のタグだけで版が変わり、変更済みのコード・未統合・未確定の版を拒否する。実際の Release 発行からの公開は初回の正式発行時に確認する |
| `ST-073-001` | `SPEC-073-001` packaging/apt/test.sh で隔離した OS に配布元を登録し、旧版の導入、状態表示、新版への更新を確認する |
| `ST-073-002` | `SPEC-073-002` packaging/apt/test.sh で更新・削除前後の保存物を比較し、署名改変後の apt update の失敗を確認する |

## 設計と結合テスト

| 識別子 | 内容 |
|---|---|
| `IDEA-073-001` | 採用: OS ごとの Python と、固定した Python 依存を同梱した専用環境。利用者の開発環境を要さず、OS の Python を変更しない |
| `IDEA-073-002` | 不採用: 導入後に pip で依存を取得する。apt の導入が外部の Python 配布サービスの状態に左右されるため |
| `AD-073-001` | Dockerfile が公開ルート証明書と HTTPS の取得先を揃えた OS をビルド・検査で共用し、固定済み依存と、Git の情報がある場所で先に作った共通の wheel を取り込み、build.sh が /usr/lib/yadori の専用環境と /usr/bin/yadori を .deb にする。指定されたアイコンを /usr/share/pixmaps/yadori.png に同梱する。OS の Python の小版を Depends で制限する |
| `AD-073-002` | repository.sh が OS ごとに一覧と署名を作る。公開先は GitHub Pages。GitHub Release の published イベントを起点に、hatch-vcs が Git タグから製品版を求め、version.sh が Release タグとの一致と main への統合を確認する。成功した同じ配布物を Release と apt へ自動発行する。PR と手動起動は検査だけで、公開鍵の秘密部分を使わない |
| `IT-073-001` | `AD-073-001` packaging/apt/test.sh の実際の導入・起動で専用環境とシステム依存が揃うことを確認する |
| `IT-073-002` | `AD-073-002` packaging/apt/test-version.sh のタグ検証と packaging/apt/test.sh の署名済み一覧取得・改変拒否で、版と配布内容の結合を確認する |

## 対象外

amd64 以外、Ubuntu 24.04 / Debian 13 以外、公式 OS 配布元への収録、自動常駐化、AI サービスへのログイン。実際の公開先への反映は初回設定と公開承認の後に行う。
