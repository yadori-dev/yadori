# 起動案内を yadori に揃える

対応する要求は [Issue #77](https://github.com/yadori-dev/yadori/issues/77) の完了条件。[配布の入口](INC-073.md)の案内を整える。会話・記憶の既存 AC は変更しない。

## 要件とシステムテスト

| 識別子 | 内容 |
|---|---|
| `SPEC-077-001` | 設定前でも `yadori --help` で全既存命令と引数の説明を標準出力へ読み、終了状態 0 で終わる。案内と現在の文書の利用例は `yadori`、開発環境の例は `uv run yadori` に揃える |
| `ST-077-001` | `SPEC-077-001` 使い捨ての未設定の保存先と任意の作業場所から導入済み命令を起こし、出力先・終了状態・全命令と引数・保存先未作成を確かめる。文書の例とヘルプの整列・折り返しは目視する |
| `SPEC-077-002` | 不正な命令と引数は引き続き標準エラーへ案内を出して終了状態 1 で終わる。既存命令の処理と内部のモジュール起動を保持する |
| `ST-077-002` | `SPEC-077-002` 知らない命令、ヘルプへの余分な引数、既存命令の誤った引数を表で渡し、標準出力が空で標準エラーと終了状態 1 が返ることを確かめる |
| `ST-077-003` | `SPEC-077-001` `SPEC-077-002` 変更前後のコードから同じ配布手順で作った deb を隔離した OS に導入し、使い捨ての設定でヘルプ、state、時点指定、不正命令を同じ操作で録画する |

## 設計と結合テスト

| 識別子 | 内容 |
|---|---|
| `AD-077-001` | 既存 Entry が単独の --help を成功として扱う。使い方の文面はエラー時と共有し、個々の命令への振り分けと配布用スクリプトは変えない。新しい解析の仕組みは加えない |
| `IT-077-001` | `AD-077-001` 導入済み命令と内部のモジュール起動へ同じヘルプ・不正入力を渡し、終了状態と両出力が一致することを確かめる |

AI 連携の応対、思い出す質、保存形式、配布の公開は対象外。
