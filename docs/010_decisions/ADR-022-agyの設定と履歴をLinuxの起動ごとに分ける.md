# ADR-022 agy の設定と履歴を Linux の起動ごとに分ける

## 判断

Antigravity CLI 1.2.1 / 1.2.2 に付き添う入口を Linux 向けに提供する。bubblewrap（起動した処理だけに別のファイル配置を見せる道具）を使い、普段の agy の設定と履歴を変更せず、一回の宿り専用の配置で起こす。これは利用者のファイル全体へのアクセスを制限する仕組みではない。作業の承認は agy が受け持つ。

宿りの名乗りと記憶を PreInvocation（モデルが返事を作る前の通知）へ渡す。主担当の正常な Stop で完成した一往復だけを記憶へ残す。読み取りと保存は既存の会話の処理を使う。下位担当・予約・背景作業と会話切替を提供しない。

## 状況と選択肢

agy の公開されている起動引数には、設定と会話履歴を専用の場所へ分ける指定を確認できない。一方、普段の設定を変更して戻す方法は、並行起動・異常終了で他の会話へ混入する。独自の対話画面で一回実行を繰り返す方法は、利用者が通常の agy で作業する要求から外れる。

一回の起動で agy が見る設定と履歴を切り替える方法を選ぶ。親のホーム環境変数と認証情報を変更せず、端末での通常の操作を保てるためである。

## 借りるものと分けるもの

本人が完了した Google アカウントでの初回案内の記録、表示設定、安全な承認・隔離設定を借りる。資格情報の中身は読まず、agy 自身が既存のログインを使う。API キーと別の接続先を使う設定では起動せず、別の課金方法へ切り替えない。追加クレジットの自動使用は有効にしない。

ホーム側の `.gemini` 全体と、作業場所・親・配下の `.agents`、`GEMINI.md`、`AGENTS.md` を専用の配置へ分ける。技能・プラグイン・MCP の継承は提供しない。使う道具は検索・ファイル編集・端末操作へ絞り、道具を呼ぶ前にも確認する。子プロセスも起動終了時に残らないよう、プロセスの見える範囲を分ける。

## 失敗時と原文の保全

agy は通知処理の非ゼロ終了だけではモデル呼び出しを止めない。通知処理の内側に期限を置き、失敗・時間切れの場合は、その通知を呼んだ agy 自体を止める。

完成した返事は、記憶への保存前に専用の回復記録へ残す。保存先が復旧したら、同じ出典の原文を再送する。保存成功直後に中断しても二重にならない。正常終了でも未保存記録がある場合は捨てない。壊れた記録や完成状態を確認できない記録は勝手に捨てず、次の起動を断って場所を示す。

## 不利益と見直す条件

bubblewrap と、利用者の権限で分離した起動ができる Linux が必要になる。普段の agy の拡張をそのまま使えず、会話切替を試みた場合は起動を終える。対応する版を限定し、通知・記録の形が変わる場合は実物との照合が必要になる。

agy が設定・履歴・読込元を正式な起動引数で分けられるようになったら、この方法を見直す。追加の道具を安全に借りる範囲を実証できたら、別の増分で対象を広げる。

## 根拠

[フックの仕様](https://antigravity.google/docs/hooks/)、[設定](https://antigravity.google/docs/cli/settings/)、[認証](https://antigravity.google/docs/cli/install/)、[bubblewrap](https://github.com/containers/bubblewrap)。実物の通知と記録の形は `backend/tests/fixtures/agy-1.2.1.json`、照合するテストは `backend/tests/test_contract_agy.py` に置く。
