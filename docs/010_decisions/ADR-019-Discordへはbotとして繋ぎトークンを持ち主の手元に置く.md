# ADR-019 Discord へは bot として繋ぎ、トークンを持ち主の手元に置く

| 項目 | 内容 |
|---|---|
| 状態 | 有効 |
| 決定日 | 2026-09-01 |

## 判断

Discord とは **bot として繋ぐ**。送るだけの仕掛け（webhook）は使わない。

受け取るのは、**持ち主本人からの直接の会話（DM）だけ**である。サーバーの部屋の言葉、他の人の言葉、自分の言葉には答えない。

Discord のトークン（Discord がその bot を見分けるための長い文字列）と持ち主のユーザーIDは、`YADORI_HOME`（既定は `~/.yadori`）の `discord.toml` に置く。**リポジトリにも、リポジトリの中のどの設定にも書かない。**

**受け取るものは、Discord へ申し込む段階で直接の会話だけに絞る。** サーバーの部屋の言葉は届かないようにし、部屋では考えている印（「入力中…」）も出さない。

**応対を作れなかった理由は Discord へ送らない。** 手元にだけ書き、Discord へは応対できないことだけを返す。

## 理由

**送るだけの仕掛けでは受け取れない。** 宿りは話しかけられて答えるものなので、受け取れない繋ぎ方はこの製品では成り立たない。加えて、宿りの側から話しかけること（`AC-008`）も、返事があったかを見て次を止める必要があるため、受け取れる繋ぎ方でないと作れない。後から乗り換えると、話す場所の実装を書き直すことになる。

**持ち主だけに絞るのは、記憶が持ち主のものだからである。** 記憶には私生活も仕事も入る（`PB-015`）。誰でも話しかけられる場所へ出すと、その記憶を踏まえた応対が他人へ渡る。宿りが複数の持ち主を扱えるようになるまで（`AC-010`）、受け取る相手を一人に固定しておくほうが、後から緩めるより安全である。

**トークンを手元に置くのは、記憶と同じ理由である。** 保存先も名乗りもリポジトリへ入れない（`ADR-006` の周辺で決めた形）。トークンは一度漏れると取り消しが要るため、同じ場所に置き、同じ規則で守る。

**理由を送らないのは、その中身が手元の様子だからである。** 応対を作れないときの理由には、手元で動かしている道具の出力がそのまま入る。そこには作業している場所や道具の内部の文言が混ざりうる。Discord は外の相手なので、端末には出してよいものでも送らない（`docs/000_process.md` §14）。

## 受け入れる不利益

bot を作る手順（開発者向けの画面で作り、自分のところへ招く）を持ち主が一度踏む必要がある。送るだけの仕掛けより手数が多い。

応対を作れなかった理由が Discord に出ないため、うまくいかないときは宿りを動かしている手元の出力を見に行くことになる。

動かし続けるのは持ち主の道具に任せるため、端末を閉じると宿りは Discord に居なくなる。常駐の形は、対応する受入基準を選んだ増分で決める（`ADR-003`）。

## 見直す条件

宿りが複数の持ち主を扱えるようになり、受け取る相手を一人に固定する理由が無くなったとき。または、Discord 以外の場所（別の連絡の道具）を足すときに、受け取り方の共通の形が要ると分かったとき。
