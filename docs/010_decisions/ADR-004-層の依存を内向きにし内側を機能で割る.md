# ADR-004 層の依存を内向きにし、内側を機能で割る

| 項目 | 内容 |
|---|---|
| 状態 | 有効 |
| 決定日 | 2026-08-31 |

## 判断

`backend/src/yadori/` を次の四層に分け、依存を内向き一方向にする。

```text
infrastructure → adapter → usecase → domain
```

各層の内側は機能で分ける（`<layer>/<feature>/`）。各層の `__init__.py` に責任と依存の向きを書く。`domain` は外の技術を知らず、保存やAIモデルの呼び出しが必要なら口（インタフェース）だけを置く。

ある機能が別の機能のデータを読む場合、データを所有する側が下になる。機能をまたぐ共通処理は、実際に二つ以上で同じ責任が現れるまで作らない。

## 理由

出ていく先は今後増える。増えるたびに変更が広がると設計が破綻するため、出ていく先ごとの違いを `adapter` の一つのディレクトリへ閉じる。

AIモデルの提供元、埋め込みの作り方、保存方法は、この道具の寿命の中で必ず入れ替わる。業務の規則（何を思い出すか、気持ちがどう動くか）がそれらを知っていると、入れ替えのたびに規則まで書き換わる。

層だけで分けると一つの機能の変更が同じディレクトリの中で散る。機能を最上位にすると同じ層の規則を機能ごとに複製しやすい。両方を避けるため、層を守った上で内側を機能で割る。

## 受け入れる不利益

単純な機能でも層を越す型と変換が必要になる。層のためだけの中継が増えないよう、機能の複雑さに応じて使う。

## 見直す条件

実装が増えても空の層が残る、または一つの変更が四層すべてへ機械的に散ることが続いた場合。
