# 外部会話を自身の記憶と分けて取り込み、起動時に準備する

## 判断

通常のClaude・Codex・agyの完成した会話を、選んだ人物が参照できる外部会話として同じSQLiteの別表へ保存する。自身の発言を表すepisodeには変換しない。自動提示とMCPの候補選択は共通にし、出典の道具名を常に本文より先に示す。

取り込みは原文と元の出典を固定して保存する。出典はファイルの場所ではなく道具・元セッション・元発話に結び、再実行と移動で重複しない。出典が同じで本文が違えば上書きせず止める。索引は原文と一往復ずつ同時確定する。

通常起動の準備は人物ごとの設定で自動・毎回確認・実行しないを選び、取り込みと自身の夢を順に各一バッチ実行する。内部の道具呼出しには準備を付けない。対象の人物と設定は選択後に固定し、同じ人物の準備を同時に行わない。

## 必要な理由

宿りとして起こす前から蓄積した会話も参照したい。既存のepisodeは名乗り版を必須とし、表示や夢で宿り自身の応対として扱うため、出典文字列だけ足すと相手を誤認する。起動の都度手動で取り込みと夢を実行する負担も減らす。

## 比較した案と不利益

既存episodeへの変換は、存在しない名乗り版を付け、通常の夢や気持ちへ混ぜるため採らない。ログを直接検索する方式は、元の移動・追記で本文と参照が変わるため採らない。外部会話の要約は新しい派生記録と夢の意味を増やすので今回は作らない。

別表と専用の検索結果を持つ分、二種類を合わせる処理が要る。一方、従来の原文と夢の意味を変えずに追加・撤回できる。保存形式の追加だけで原文の移行や破棄を行わない。

## 見直す条件

外部会話自体の整理・要約や常時同期を求められた場合に、出典付きの派生記録と同期契約を別途検討する。通常CLIの完了・分岐の形式が変わった場合は、未対応を明示して実物契約を更新する。
