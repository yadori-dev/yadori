# ADR-012 会話の入口を、思い出すと覚えるの二つに分ける

| 項目 | 内容 |
|---|---|
| 状態 | 有効 |
| 決定日 | 2026-08-31 |

## 判断

会話に関わる入口を、**思い出す**と**覚える**の二つに分ける。この二つが一組であることが名前から読めるようにし、どちらも同じ場所（`usecase`）へ置く。

```text
思い出す(誰の宿りか, 話しかけられた文章)
    → 関係する記憶 と 名乗り と 今の状態

（返事が作られる。誰が作るかは出ていく先による）

覚える(誰の宿りか, 話しかけられた文章, 返事)
    → 記憶が増え、気持ちが動き、気がかりが生まれる
```

入口の中の各段は、**会話の出来事**の名前で呼ぶ。保存先や仕組みの名前（「感情を注入する」など）で呼ばない。状態の種類を足しても入口の段が増えない形にする。

## 理由

一度の会話は「思い出して、話して、覚える」という一つの輪だが、[ADR-002](ADR-002-常駐する本体を宿りとし話す場所を出ていく先とする.md) の形では返事を作るのが本体とは限らないため、一つの関数の中では閉じられない。前半と後半が別の時点で呼ばれる。

このとき二つを別々の場所へ置くと、覚える側の処理がアダプタやフックの中へ散り、輪が見えなくなる。宿りの状態が変わるのは覚える側なので、そこが散ると、なぜ性格が動いたのかを追えなくなる。

段を「注入する」のような仕組みの言葉で呼ぶと、種類が増えるたびに入口を書き換えることになり、[ADR-005](ADR-005-記憶を減衰の速さが違う一つの仕組みとして持つ.md) で一つにまとめた意味が失われる。

## 受け入れる不利益

出ていく先によっては、思い出してから覚えるまでの間が長く空き、その間に状態が変わりうる。どの時点の状態で返事が作られたかを、記録しておく必要がある。

## 見直す条件

思い出すと覚えるの間に、両方が知る必要のある状態が増え、二つに分けたことで受け渡しが複雑になったとき。
