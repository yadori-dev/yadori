# ADR-003 立ち上げで決める技術を三つに限る

| 項目 | 内容 |
|---|---|
| 状態 | 有効 |
| 決定日 | 2026-08-31 |

## 判断

立ち上げでは、次の三つだけを決めた。

- 実装言語は Python
- 本体は常駐し、外からは手元の HTTP で話しかける
- 記憶の保存先は手元のファイルひとつ（SQLite）から始める

模型の提供元、埋め込みの作り方、ベクトル検索の実装、出ていく先の数、配布方法は、対応する受入基準を選んだ増分で決める。最初からプロセスを複数へ分けない。

## 理由

空の段階で技術を決めると、要求から導けない制約を先に作る。

Python は要求から一意に導いた選択ではない。埋め込みとベクトル検索の道具が揃っていること、模型の提供元を差し替える費用が小さいことを、立ち上げの費用が小さい理由として選んだ。

HTTP にするのは、出ていく先が複数あり、それぞれ別のプロセスとして動くためである。ひとつの記憶を複数の場所から同時に触る必要がある。

## 受け入れる不利益

Python は単一の実行ファイルとして配れない。利用者は実行環境を用意する必要がある。また、出ていく先のフック（発話の直前に割り込む仕組み）は会話のたびに通るため、そこで毎回インタプリタを起動すると会話全体が遅くなる。フックは常駐している本体へ問い合わせるだけの薄いものにする。

## 見直す条件

Python または単一プロセスが、選んだ受入基準を満たせない具体的な制約になったとき。
