# ADR-017 実際の会話の記録を、判定のために対話する道具へ渡す

| 項目 | 内容 |
|---|---|
| 状態 | 有効 |
| 決定日 | 2026-08-31 |

## 判断

評価セットの下書きを作るとき、**持ち主の実際の会話の記録を、後の発話が前のどの話題を指すかの判定のために、手元の対話する道具（Claude Code）へ渡す**。渡すのは、後の発話と、宿りの思い出す仕組み（文を数字に変えて意味の近さで探す。測られる側と同じもの）が引いた前の発話の候補（数件）の文章だけで、返事、時刻、作業場所は渡さない。作業場所の発話を丸ごと渡すことはしない。道具の文脈は外して呼ぶ（[ADR-016](ADR-016-応対は対話する道具を通して作り、その道具の文脈を持ち込まない.md) と同じ呼び方）。

どの記録を渡すかは、持ち主がディレクトリを指すことで選ぶ。使い方に、どの記録がどの相手へ渡るかを書き、実行する前に読める。

## 必要になった状況

思い出す質は実際の会話から作った評価セットで測る（[ADR-010](ADR-010-思い出す質を評価セットで判定する.md)）が、その評価セットは人が記録を読んで一問ずつ書き写しており、数十問が限度だった。後の発話が前のどの話題を指すかを機械に候補として出させる必要があり、その判定には文章の意味を読む何かが要る。

## 選択肢

1. 人が全部読む。続かない
2. 測られる側の埋め込みで近い組を候補にし、人がそのまま確かめる。埋め込みが拾えない組は評価セットから消える。候補が多いと人が読み切れない
3. 2 で引いた候補だけを対話する道具に渡し、同じ話題かを判定させる。渡すものが小さく、定額契約の範囲で動く。埋め込みの盲点は人が手で足す。**採る**
4. 作業場所の発話を丸ごと道具に渡して組を全部挙げさせる。数百発話で十万トークン級になる。実装して確かめ、採らない
5. 別の提供元のAIモデルへ鍵で繋いで判定させる。従量課金になり、渡る相手も増える

## 理由

宿りは必要な記憶だけを渡すための道具であり、その周辺の道具も同じ前提で作る。3 は、渡すものを発話と数件の候補に抑えたまま、話題が同じかを別の頭で決められ、鍵も課金も増やさない。4 はその前提と逆で、繰り返し使える道具にならなかった。Claude Code の記録については、その会話が普段通っている相手と同じ相手へ渡るため、新しい経路が生まれない。

## 受け入れる不利益

**Codex の記録は、今まで渡っていなかった相手へ渡る。** 渡してしまった後では戻せない。持ち主がディレクトリを指して選ぶ形にし、使い方に書いて事前に読めるようにするが、渡すこと自体は避けない。

判定に定額契約の上限を消費する。上限に当たると宿りの応対まで使えなくなる。上限に当たれば下書きを書かずに断る。

**下書きは、今の埋め込みが引けた候補だけからできる。** この評価セットで埋め込みや近さの下限を比べると、引いた側の埋め込みに有利に偏る。下限を緩め件数を多く取ること、人が手で問を足すこと、架空の評価セットを併用すること、既定の埋め込みを替えたら下書きを引き直すことで受ける。

## 見直す条件

手元で動くAIモデルで判定の質が足りると測って確かめられたとき（外へ渡さずに済む）。判定のために渡した会話が意図しない用途へ使われることが分かったとき。
