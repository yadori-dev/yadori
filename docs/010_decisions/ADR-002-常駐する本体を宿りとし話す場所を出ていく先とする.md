# ADR-002 常駐する本体を宿りとし、話す場所を出ていく先とする

| 項目 | 内容 |
|---|---|
| 状態 | 有効 |
| 決定日 | 2026-08-31 |

## 判断

宿りの本体は、話しかけられていなくても動き続けるひとつの常駐プログラムとする。Discord、Claude Code、Codex、Gemini は、その本体が出ていく先（アダプタ）として扱う。

出ていく先は本体に対して二つの口だけを使う。

- **思い出す**: 発話を渡すと、関係する記憶と現在の状態を返す
- **覚える**: 一度のやりとりを渡すと、記憶が増え、状態が動く

返事の文章を誰が作るかは出ていく先ごとに違う。Discord では本体がAIモデルを呼んで自分の言葉で話す。Claude Code などでは各道具が返事を作り、本体は思い出した内容を渡すだけである。この違いはアダプタの中に閉じ、本体の口は変えない。

## 理由

宿りを「呼ばれたときだけ動くもの」にすると、記憶の整理と、話しかけられていない間に気づくことが成立しない。夢と、宿りから話しかける機能は、会話が無い時間に動く必要がある。

出ていく先を外から呼ぶ形（本体が  などを子プロセスとして起動する形）も検討した。この形でも道具ごとの起動方法と出力形式の違いは残るため、アダプタを書く手間は変わらない。一方で、対話型の道具が持つファイル操作や実行の能力を利用者が使えなくなる。同じ費用で得られるものが少ないため採らない。

## 受け入れる不利益

Claude Code などでは返事の文章を本体が作らないため、出ていく先ごとに口調と判断が揺れる。宿りが同じ人物として一貫するのは、記憶と状態の範囲までである。この揺れを消そうとせず、Discord を宿りが自分の言葉で話す場所として扱う。

## 見直す条件

対話型の道具の側が、外部から人格と記憶を差し込む正式な仕組みを持ったとき。または、出ていく先ごとの揺れが利用者にとって同一人物と認められない水準になったとき。
