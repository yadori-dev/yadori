# ADR-002 常駐する本体を宿りとし、話す場所を出ていく先とする

| 項目 | 内容 |
|---|---|
| 状態 | 有効 |
| 決定日 | 2026-08-31 |

## 判断

宿りの本体は、話しかけられていなくても動き続けるひとつの常駐プログラムとする。Discord、Claude Code、Codex、Gemini は、その本体が出ていく先（アダプタ）として扱う。

出ていく先は本体に対して二つの口だけを使う。

- **思い出す**: 発話を渡すと、関係する記憶と現在の状態を返す
- **覚える**: 一度のやりとりを渡すと、記憶が増え、状態が動く

返事の文章を誰が作るかは出ていく先ごとに違う。Discord では本体がAIモデルを呼んで自分の言葉で話す。Claude Code などでは各道具が返事を作り、本体は名乗りと思い出した内容を渡す。この違いはアダプタの中に閉じ、本体の口は変えない。

## 理由

宿りを「呼ばれたときだけ動くもの」にすると、記憶の整理と、話しかけられていない間に気づくことが成立しない。夢と、宿りから話しかける機能は、会話が無い時間に動く必要がある。

出ていく先を、本体が利用者の代わりに非対話で呼び、完成した返事だけを利用者へ渡す形も検討した。その形では、対話型の道具が持つファイル操作や実行の能力を利用者が直接使えないため採らない。

利用者が対話型の道具をそのまま操作でき、本体は思い出すと覚えるの二つだけを差し込む形はこれと異なる。その道具を子プロセスとして起こしても、同じ端末につなぎ、利用者が直接操作できるなら、この判断と矛盾しない。

## 受け入れる不利益

Claude Code などでは返事の文章を本体が作らないため、渡した名乗りに従う範囲でも、出ていく先ごとに細かな言い回しと判断が揺れる。記憶と状態は本体の一つだけを正とし、各道具が独自に積んだ記憶は使わない。

## 見直す条件

対話型の道具の側が、外部から人格と記憶を差し込む正式な仕組みを持ったとき。または、出ていく先ごとの揺れが利用者にとって同一人物と認められない水準になったとき。
