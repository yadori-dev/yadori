# 追加検索を起動と往復に結びMCPで公開する

## 判断

Codex/Claude/agyの宿りとしての起動に、MCPの検索と原文取得だけを組み込む。接続はローカルの標準入出力を使い、対象の人物と保存先は起動時の設定に固定する。既存の設定スナップショットを引き継ぎ、モデルの引数から人物を選ばせない。

一往復の不透明なキーをフックで渡し、全呼出しで照合する。起動専用領域のSQLiteが参照・回数・応答量を原子的に保持し、再接続で予算を復活させない。検索は短い候補だけ返し、全文は別の取得で頁ごとに返す。詳しい上限と停止条件は [INC-082](../210_increments/INC-082.md) に置く。

検索・取得は原文や思い出した回数を変更しない。台帳は起動中の追跡用で、終了時に現在の専用履歴とともに破棄する。

## 選択肢と理由

会話の `recall` をそのまま呼ぶと名乗り・気持ち・直近・夢を重ねて返し、思い出した回数も増えるため採らない。シェルコマンドだけを足す方式は、相手が発見して自発的に呼べる接続を別に必要とするため初回の入口にしない。

[MCP公式Python SDK](https://github.com/modelcontextprotocol/python-sdk) を使う。接続処理を独自実装せず、stdioとクライアントの互換性は実物の契約テストで確かめる。

## 不利益と見直す条件

道具の説明や追加のモデル往復が増えるため、常にトークンを節約できるわけではない。自動検索のみと候補全文の一括提示を対照に、実際の量と待ち時間を測る。

サーバーが制限するのは受け付ける記憶処理とその応答量であり、モデルやホストの対話全体ではない。上限後も相手が応対へ戻らない場合は利用体験が未達であり、接続または指示の見直しが必要になる。
